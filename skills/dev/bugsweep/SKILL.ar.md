# /bugsweep — سير عمل المسح المنهجي للأخطاء

بحث تكراري عن الأخطاء بمعيار توقف متقارب. يتدرّج بحسب حجم قاعدة الشيفرة، ويتصاعد عند الشك في أن البحث سطحي، ويمنع التكرار من خلال تتبّع المجالات.

## 1. حساب المعدل الأساسي

```
LOC = produktive Quellzeilen (src/, lib/ — ohne Tests, Configs, Docs, generated)
x = max(1, ceil(LOC / 1500))
Grundrate = x * 3
```

| LOC | x | المعدل الأساسي |
|-----|---|-----------|
| ~1500 | 1 | 3 |
| ~3000 | 2 | 6 |
| ~4500 | 3 | 9 |
| ~10000 | 7 | 21 |

أبلغ المستخدم: "قاعدة الشيفرة: {LOC} LOC ← المعدل الأساسي = {Grundrate} عمليات بحث نظيفة."

## 2. حلقة البحث

```
zähler = 0
ziel = Grundrate
je_bug_gefunden = False
geprüft = []  # (bereich_name, typ: code|aufgabe)

LOOP:
  bereich = wähle_neuen_bereich()  # Siehe Bereichs-Regeln
  geprüft.append(bereich)
  
  Führe gründliche Bug-Suche durch
  
  IF Bug gefunden:
    je_bug_gefunden = True
    Fix nach bugfix-protocol (Phase 4+5)
    Review: siehe Modell-Regel (neuere Modellklassen: kein externer Review nötig)
    Commit + Push
    zähler = 0  # RESET
  ELSE:
    zähler += 1
    Melde: "✓ Sauber: {bereich} — {zähler}/{ziel}"
  
  IF zähler >= ziel:
    IF NOT je_bug_gefunden:
      # Verdoppelungs-Eskalation: kein einziger Bug → zu oberflächlich?
      ziel = Grundrate * 2
      je_bug_gefunden = True  # Eskalation nur EINMAL
      Melde: "⚠ Kein Bug in {Grundrate} Läufen → Ziel verdoppelt auf {ziel}."
      CONTINUE LOOP
    ELSE:
      GOTO Abschluss-Verifikation
```

### ملاحظات عملية حول حلقة البحث (مستخلصة من عمليات المسح)

- **مستودعات غير Git:** حيث لا يتوفر `git` (مثل مجلدات المشاريع المزامَنة مع السحابة)، يحل **نسخ احتياطي مُرقَّم الإصدار** محل "الإيداع + الدفع": أنشئ `datei_<ts>.bak` قبل أول إصلاح. **تنبيه — النسخ الاحتياطي السابق للإصلاح ليس حماية للعمل:** بعد آخر إصلاح اسحب نسخة `_FINAL_` جديدة، وإلا ضاع كل عمل الإصلاح عند أي خلل في المزامنة.
- **أخطاء كثيرة معروفة مسبقًا:** إذا كانت N أخطاء معروفة عند البدء (مثلًا من تشغيل سابق)، فإن "لكل خطأ: إصلاح ← مراجعة ← إيداع ← إعادة تعيين" غير عملي. عندها عالج الأخطاء المعروفة ككتلة إصلاح واحدة (مراجعة مشتركة في النهاية)، واحسب المعدل الأساسي وحلقة البحث بدءًا من أول خطأ جديد. يبقى منطق إعادة التعيين ساريًا للأخطاء الجديدة المكتشفة أثناء المسح.
- **الخطأ نفسه في عدة مواضع:** غالبًا ما يُنسخ الخطأ المكتشف (مثل تعبير نمطي خاطئ، أو افتراض تنسيق معطوب) إلى مواضع أخرى. بعد كل إصلاح تحقّق بالبحث مما إذا كان النمط نفسه موجودًا في مكان آخر — وهذا "مجال" مستقل ومجدٍ.

## 3. قواعد المجالات (ضد التلاعب)

المجال هو إما **تركيز على الشيفرة** أو **مهمة** (غرض الشيفرة).

### تركيز على الشيفرة
- يجوز **توسيعه** بين التشغيلات (ملفات أكثر) أو **نقله** (جزء آخر)
- لا يجوز أن يكون الاختيار مطابقًا تمامًا لتشغيل سابق
- مثال مقبول: التشغيل 1 = `maintenance.py`، التشغيل 5 = `maintenance.py + orchestrator.py` (موسّع)
- مثال غير مقبول: التشغيل 1 = `maintenance.py`، التشغيل 5 = `maintenance.py` (متطابق)

### مهمة (غرض)
- يجوز طرحها **بتفصيل أكبر** (فحص دالة فرعية) أو **أوسع** (دوال مترابطة)
- لا يجوز أن تكون المهمة نفسها تمامًا
- مثال مقبول: التشغيل 1 = "أمان الخيوط في المراقِب"، التشغيل 5 = "أمان الخيوط في علبة النظام كاملًا" (أوسع)
- مثال مقبول: التشغيل 1 = "اكتشاف العمليات"، التشغيل 5 = "مطابقة علامات المخزن في اكتشاف العمليات" (أدق)
- مثال غير مقبول: التشغيل 1 = "أمان الخيوط في المراقِب"، التشغيل 5 = "أمان الخيوط في المراقِب" (متطابق)

### التسمية
- يجب تسمية المجال **قبل** البحث (لا تعيين لاحق)
- التنسيق: `"{Name}" ({typ}: code|aufgabe)`

## 4. التحقق النهائي

بعد أن يصبح العداد ≥ الهدف **و** وُجد خطأ واحد على الأقل:

**الخطوة أ — bugfix-protocol المرحلة 5:**
- [ ] مجموعة الاختبارات الكاملة خضراء (`pytest`)
- [ ] **تنفيذ المسار الفعلي المُعدَّل مرة واحدة على الأقل** — لا الاختبارات وحدها. الاختبارات الوحدوية الخضراء على شيفرة لا تستدعي الموضع المُعدَّل وهم أمان. نفّذ المسار المُعدَّل فعليًا (تشغيل تجريبي، أو اختبار دخان، أو استدعاء سطر الأوامر) وتحقق من التتبعات / أخطاء التوقيع / الأسماء. `py_compile` أو الاستيراد وحده يتحقق من بناء الجملة فقط — لا من أن المسار يعمل.
- [ ] **لكل إصلاح اختبار واحد على الأقل يمسّه** — الإصلاح الذي لا يُفعّل فرعه المُعدَّل أي اختبار يُعدّ غير مُتحقَّق منه (لمسارات التنسيق/الشبكة يُجمع عند الحاجة بين المحاكاة والتشغيل التجريبي).
- [ ] فحص الأنواع (إن كان مُهيّأً)
- [ ] فحص الأسلوب (lint) (إن كان مُهيّأً)
- [ ] فحص حالات الحد لإصلاحات الجلسة

**الخطوة ب — المراجعة (قاعدة النموذج):**
- **فئات النماذج الأحدث (مثل Claude 5 / فئة Fable):** لا حاجة إلى مراجعة خارجية من مستشار/نموذج ثانٍ.
  الخطوة أ (الاختبارات + اختبار الدخان الفعلي) هي التحقق. اختياريًا عند عدم يقين حقيقي: وكيل مراجعة جديد — لكن تُتحقَّق تجريبيًا من نتائجه (اختبار ضد الشيفرة غير المُعدَّلة) قبل اعتبارها خطأً.
  الخلفية (تجربة المسح 2026-06-11): لم يكن المراجِع الثاني متاحًا، فأعطى الوكيل البديل نتيجة واحدة (ثقة 85)، ثبت عبر اختبار أنها ليست خطأً — ولم تغيّر المراجعة الخارجية النتيجة.
- **النماذج الأقدم:** مناقشة ختامية مع المستشار (احتياطيًا: نموذج ثانٍ كمراجع)؛ يؤكد المستشار أو يجد ثغرات.

**عند اكتشاف خطأ أثناء التحقق:**
→ إصلاح + اختبار + إيداع
→ إعادة التعيين: العداد = 0، الهدف = المعدل الأساسي (جديد، **دون** مضاعفة)
→ العودة إلى حلقة البحث (تبقى قائمة المفحوص، وتصبح je_bug_gefunden = True)

**عند تحقق نظيف:**
→ انتهى. إيداع + دفع. أخرِج البروتوكول.

## 5. البروتوكول (في النهاية)

```markdown
## Bug-Sweep Ergebnis

- **Codebasis:** {LOC} LOC
- **Grundrate:** {Grundrate} (eskaliert: {ziel})
- **Geprüfte Bereiche:** {len(geprüft)}
- **Bugs gefunden:** {anzahl}
- **Resets:** {anzahl_resets}
- **Verdoppelung ausgelöst:** ja/nein
- **Fixes:**
  - {titel} — {commit_hash}
  - ...
- **Finale Test-Suite:** {passed}/{total} grün
- **Review-Verdict:** Selbstverifikation (neuere Modellklasse) / Advisor bestätigt / Lücken benannt
```

## متى تستخدم هذا السير

- بعد تطوير الميزات (ضمان الجودة)
- قبل الإصدار (مسح القبول)
- دوريًا كفحص نظافة
- عندما يكتب المستخدم `/bugsweep`

## التفاعل مع المهارات الأخرى

- **bugfix-protocol:** إجراء الإصلاح (المرحلتان 4 و5) لكل خطأ مكتشف
- **systematic-debugging:** للأخطاء الصعبة الإعادة ضمن المسح
- **code-review:** يمكن استخدامه كمجال مهمة
