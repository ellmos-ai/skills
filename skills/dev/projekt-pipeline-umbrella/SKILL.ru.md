# Создание и Реструктуризация Проектов/Пайплайнов — Umbrella

## Назначение

Точка входа для семейства «Создание и реструктуризация проектов/пайплайнов». Его участники упорядочены по двум осям: **Greenfield vs. Существующее** и **Уровень проекта vs. Уровень пайплайна**. Этот Umbrella предотвращает частую путаницу между "bootstrap", "optimize" и "onboard".

## Участники и Маршрутизация (Routing)

| Навык | Для чего | Когда использовать этот навык вместо других |
|-------|-------|-------------------------------|
| `/project-bootstrapper` | Создать НОВЫЙ проект **в** существующем пайплайне | Greenfield, Уровень проекта |
| `/pipeline-bootstrapper` | Создать С СУЩЕСТВА НОВЫЙ пайплайн верхнего уровня | Greenfield, Уровень пайплайна (редко) |
| `/project-onboarding` | Принять/зафиксировать существующий проект | Существующее, Уровень проекта |
| `/pipeline-optimizer` | Реконструировать существующий пайплайн/структуру (по 6-шаговой процедуре) | Существующее, Реструктуризация |
| `/docs-analysis` | Проверить документы требований/концепций на соответствие текущему коду | Существующее, Анализ (без реструктуризации) |
| `/dev-cycle` | 8-фазный фреймворк разработки для непосредственного построения | Сквозной: КАК производить разработку |

> Правило маршрутизации: **новое + проект** → `/project-bootstrapper` · **новое + пайплайн** → `/pipeline-bootstrapper` · **принять существующее** → `/project-onboarding` · **реструктурировать существующее** → `/pipeline-optimizer` · **только проверить** → `/docs-analysis` · **строить/разрабатывать** → `/dev-cycle`.

## Хорошо сочетаемые комбинации

- `/project-onboarding` (сначала: зафиксировать существующее) → `/pipeline-optimizer` (затем: прицельно реструктурировать) — сначала понять, потом реконструировать (реализует 6-шаговый принцип «сначала прочитай, потом пиши»).
- `/docs-analysis` (найти пробелы) → `/dev-cycle` (устранить пробелы).
- `/project-bootstrapper` (каркас) → `/dev-cycle` (разработать содержимое).

## Общие соглашения

- Всегда сначала читайте существующие соглашения пайплайна (Registry, Templates, CLAUDE.md) — не создавайте параллельных стандартов.
- Навыки Greenfield создают, навыки для существующего — реконструируют; не смешивайте их.
- Перед применением читайте актуальные рабочие файлы отдельных навыков.
