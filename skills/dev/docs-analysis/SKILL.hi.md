# दस्तावेज़-आवश्यकता विश्लेषण

> सभी अवधारणा और आवश्यकता दस्तावेज़ों का विश्लेषण करता है, उनकी आवश्यकताओं की वर्तमान कोड से जाँच करता है, और एक समेकित अंतर रिपोर्ट तैयार करता है।

---

## उद्देश्य

../docs/ फ़ोल्डर में सभी अवधारणा और आवश्यकता दस्तावेज़ों का विश्लेषण करता है, उनकी आवश्यकताओं की वर्तमान कोड से जाँच करता है, और एक समेकित अंतर रिपोर्ट तैयार करता है।

---

## नामकरण परंपरा

### उपसर्ग और प्रत्यय
सभी विश्लेषित दस्तावेज़ों को यह मिलता है:
- **उपसर्ग:** `conN_` जहाँ N = विश्लेषण संस्करण (1, 2, 3, ...)
- **प्रत्यय:** `_XX` जहाँ XX = प्रतिशत में पूर्ति स्तर (10 के गुणज में पूर्णांकित)

### संग्रहण सीमा
- **>= 75% पूरा:** दस्तावेज़ `../docs/_archive/` में स्थानांतरित होता है
- **< 75% पूरा:** दस्तावेज़ उपसर्ग/प्रत्यय के साथ `../docs/` में रहता है
- **सीमा कॉन्फ़िगर योग्य** (डिफ़ॉल्ट: 75)

---

## प्रक्रिया

### चरण 1: दस्तावेज़ एकत्र करें
- ../docs/ (मूल) में सभी *.md और *.txt फ़ाइलों की सूची बनाएँ
- README.txt को छानकर हटाएँ

### चरण 2: आवश्यकताएँ निकालें
प्रत्येक दस्तावेज़ के लिए:
- सामग्री पढ़ें
- आवश्यकताओं की पहचान करें (चेकलिस्ट, तालिकाएँ, FEHLT/TODO चिह्न)
- वर्गीकृत करें: संरचना, कोड, API, DB-स्कीमा, CLI, फ़ीचर

### चरण 3: कोड जाँच
प्रत्येक आवश्यकता के लिए:
- जाँच विधि तय करें (Glob, Grep, Read)
- जाँच करें
- चिह्नित करें: ERFUELLT (पूरा), TEILWEISE (आंशिक), FEHLT (गायब)

### चरण 4: मूल्यांकन
- पूरी और खुली आवश्यकताओं की गिनती करें
- पूर्ति स्तर (%) की गणना करें
- निर्णय लें: संग्रहित करें (>= 75%) या रखें (< 75%)

### चरण 5: आउटपुट तैयार करें
- ANFORDERUNGSANALYSE.md (सारांश) बनाएँ
- consense_diff.md (केवल खुली आवश्यकताएँ, प्राथमिकता के अनुसार) बनाएँ

### चरण 6: संस्करण प्रबंधन
- उच्चतम conN_ उपसर्ग खोजें
- नया संस्करण = उच्चतम + 1

### चरण 7: नाम बदलें और स्थानांतरित करें
- दस्तावेज़ों पर नया उपसर्ग/प्रत्यय लगाएँ
- संग्रहित करें या रखें

---

## आउटपुट

| फ़ाइल | विवरण |
|-------|--------------|
| `conN_ANFORDERUNGSANALYSE.md` | पूर्ण विश्लेषण (संस्करण N) |
| `consense_diff_N.md` | समेकित खुली आवश्यकताएँ |
| `_archive/conN_*_XX.*` | संग्रहित (>=75%) दस्तावेज़ |
