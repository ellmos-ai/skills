# mermaid-lint

يعرض مخطط Mermaid يحتوي على خطأ في بناء الجملة على GitHub، بدلاً من الرسم، المربع
**"Unable to render rich display"**. محلياً لا يُلاحظ ذلك، لأن لا أداة تفحص الكتلة.
تسدّ هذه المهارة هذه الفجوة.

## متى تُطبَّق

- يعرض README أو مستند على GitHub خطأ عرض بدلاً من المخطط.
- قبل النشر أو إصدار نسخة تحتوي مخططات في التوثيق.
- بعد كل إعادة هيكلة لـ Markdown تمس كتل Mermaid.
- على نطاق واسع عبر عدة مستودعات، عندما لا يكون واضحاً أين يوجد عطل.

## الأداتان

### 1. `mermaid_lint.mjs` — فحص بناء الجملة دون متصفح

```
node mermaid_lint.mjs <repo-pfad> [...] [--json]
node mermaid_lint.mjs --from <liste.txt> [--json]
```

يبحث تكرارياً عن جميع ملفات `.md`، ويستخرج كل كتلة ```mermaid، ويمررها
عبر `mermaid.parse()` — **نفس المحلل الذي يستخدمه GitHub في المتصفح**.
الخروج 0 = كل شيء يُحلَّل بنجاح، الخروج 1 = كتلة واحدة معطوبة على الأقل. يذكر الناتج الملف ورقم الكتلة والسطر وخطأ المحلل الحرفي.

يقرأ `--from <datei>` قائمة مسارات، مساراً في كل سطر. استخدم ذلك بدلاً من وسائط كثيرة:
تُفسد مسارات Windows التي تحتوي على Backslash بصمت في صدفة Bash (يتحول `D:\code\my-repo` إلى `D:codemy-repo`). اكتب المسارات بشرطة مائلة للأمام (Forward-Slashes).

عملية واحدة تكفي لمئات المستودعات لأن Mermaid يُحمَّل مرة واحدة فقط. لا Puppeteer ولا تنزيل Chromium.

### 2. `readback.mjs` — إثبات على الصفحة الحية

```
node readback.mjs <github-url> [...]
```

يفتح الصفحات في متصفح Edge المثبت (دون تنزيل متصفح) ويحسب أخطاء العرض الحقيقية. الحكم لكل صفحة: `OK` أو `DEFEKT` أو `UNKLAR` أو `KEIN-MERMAID`.

## ثلاثة مزالق تجعل هذه المهارة ضرورية

**يعرض GitHub مخططات Mermaid داخل iframes معزولة ضمن `viewscreen.githubusercontent.com`.**
لا ترى الصفحة الرئيسية محتواها. من يقيّم فقط `document.body.innerText` أو `msedge --dump-dom`، يتلقى على **كل** صفحة صفر أخطاء — حتى على صفحة معطوبة ثبت ذلك. لذلك يقيّم `readback.mjs` جميع الإطارات.

**نتيجة DEFEKT منفردة غير موثوقة.** أثناء التحميل يعرض GitHub لفترة قصيرة عنصراً نائباً يبدو كخطأ عرض. وفق القياس بتاريخ 2026-09-20: أبلغت الصفحة نفسها أولاً عن `ERR=1`، ثم مرتين عن `ERR=0`. لذلك يعيد `readback.mjs` تلقائياً النتائج السلبية، أما `OK` فلا يُعاد أبداً.

**يحتاج `mermaid.parse()` إلى DOM**، وإلا يفشل عند `DOMPurify.addHook` ويبلغ عن مخططات تدفق صحيحة بوصفها معطوبة خطأً. يجهّز `mermaid_lint.mjs` مسبقاً نافذة jsdom. وإذا بقي خطأ في البيئة، فإنه يُسجَّل بشكل منفصل تحت `envIssues` و**لا** يُحتسب كخطأ في بناء الجملة.

## التحقق دائماً بعينة تحكم سلبية

قبل أن تصدّق نتيجة خضراء، شغّل الأداة مرة واحدة على حالة تعرف أنها معطوبة — مثلاً الكوميت الذي سبق إصلاحك:

```
node readback.mjs "https://github.com/<org>/<repo>/blob/<alter-sha>/README.md"
```

إذا أبلغت هي أيضاً عن `OK`، فإن قراءتك العكسية لا تقيس شيئاً. وبهذه الطريقة اكتُشف مزلق iframe أعلاه.

## أسباب شائعة للأخطاء والمعالجة الأقل تدخلاً

| العَرَض في خطأ المحلل | السبب | المعالجة |
|---|---|---|
| `Expecting '+', '-', '()', 'ACTOR', got 'loop'` | اسم المشارك مطابق لكلمة محجوزة: `loop`، `alt`، `opt`، `par`، `end`، `critical`، `break`، `rect`، `note` | صرّح بالاسم المستعار: `participant L as Loop`، والرسائل تستخدم `L`. **يبقى الاسم المعروض** — لا تُعِد التسمية. |
| `got 'PS'` في مخطط تدفق | أقواس دائرية في تسمية العقدة | ضع التسمية بين علامتي اقتباس: `A["Start (hier)"]` |
| `Lexical error ... Unrecognized text` | علامات الاقتباس الخلفية (Backticks) أو النقطتان (:) في التسمية | ضع التسمية بين علامتي اقتباس، وأزل علامات الاقتباس الخلفية |
| `Expecting 'SEMI', 'NEWLINE', 'EOF'` في `graph`/`flowchart` | `Note:` موجود فقط في مخططات التسلسل ومخططات الفئات | انقل نص الملاحظة من الكتلة وضعه كسطر Markdown تحتها، حتى تبقى المعلومة مرئية |
| `Expecting 'SOLID_OPEN_ARROW' ... got 'NEWLINE'` في مخطط تسلسل | **كيان HTML** في نص الرسالة (`&lambda;`، `&Delta;`، `&ge;`). لا تسبب الأقواس ولا `=` العطل هنا — فالـ `;` الختامي للكيان يقرؤه المحلل المعجمي بوصفه منهي العبارة، وكل ما يليه يصبح عبارة جديدة. | استبدل الكيان بالحرف الحرفي (λ، Δ، ≥)، ولا تغيّر النص بخلاف ذلك. يجوز إبقاء الأقواس. لا تغيّر القيم العددية وطريقة كتابتها أبداً. |
| الفاصلة المنقوطة في رسالة تسلسل | تُقرأ كنهاية عبارة | استبدلها بـ ` - ` |

في **تسميات مخططات التدفق المحاطة بعلامات اقتباس** لا تشكّل الكيانات مشكلة — القاعدة تنطبق فقط على رسائل التسلسل. يُبلغ `mermaid_lint.mjs` عن هذه الكيانات بسطر `[WARN]` مستقل (الحقل `warnings` في JSON)، إضافة إلى خطأ المحلل: فالمحلل يقول فقط `got 'NEWLINE'` ولا يذكر السبب.

**المبدأ:** تدخل محدود إلى أقصى حد. يبقى التخطيط ومعرّفات العقد والترتيب والنص المرئي دون تغيير قدر الإمكان. في مستودعات البحث العلمي ينطبق ذلك بشكل خاص على القيم العددية وطريقة كتابتها. عند تكافؤ EN/DE أبقِ الصيغتين متطابقتين في البنية.

## سير العمل عبر عدة مستودعات

1. جرد عبر `gh repo list <org> --limit 200 --json name,isArchived,isPrivate,defaultBranchRef`.
2. **اسحب النسخ المستنسخة إلى حالة الريموت** وخذ الاختلافات بجدية. الفحص (lint) على نسخة مستنسخة قديمة يقيس الحالة الخاطئة. إذا فشل `git pull --ff-only`، فتحقق مقابل `origin` بدلاً من شجرة العمل: `git archive origin/<branch> | tar -x -C <tempdir>` ثم افحص المجلد المؤقت.
3. **مستودعات بالاسم نفسه من منظمات مختلفة** (نموذجياً `.github`) لا يجوز ربطها بالنسخة المستنسخة نفسها، وإلا تفحص المستودع نفسه تسع مرات. عند تكرار الاسم، استنسخ بشكل مسطح إلى `<org>__<repo>` وافحص الحالة الحديثة.
4. قبل كل تعديل تحقّق من الأقفال (`lock_scan.py`، و`LOCK*.txt` في النسخة المستنسخة **و** في مسار مشروع OneDrive)، ثم ضع قفلك الخاص، وأزله بعد الدفع. **اقرأ النطاق (Scope)، لا مجرد الوجود:** `LOCK.team.*` منتهي الصلاحية مع `expires_after` يمكن تجاهله؛ أما `LOCK.user.zenodo-upload.txt` فيقفل حصراً عملية الكتابة الخارجية إلى Zenodo ويسمح صراحةً بتعديلات التوثيق. في المقابل، فإن `LOCK.user.until-winners-announcement.txt` (Judging) يقفل كل عملية دفع — هناك افحص بالقراءة فقط وسجّل النتيجة كتذكرة.
5. أصلح، وافحص حتى تصبح النتيجة خضراء، ثم نفّذ commit، ثم `git pull --rebase`، ثم ادفع (push).
6. قراءة عكسية مع عينة تحكم سلبية. عندها فقط يُعتبر الأمر منجزاً.

## الإعداد

```
npm install mermaid jsdom playwright-core
```

في مجلد السكربتات أو على مستوى النظام؛ يستخدم `playwright-core` متصفح Edge المثبت (`channel: 'msedge'`) ولا يُنزّل متصفحاً خاصاً به. مطلوب فقط للقراءة العكسية، أما فحص بناء الجملة فيعمل بدونه.

## ذو صلة

- `_tools/lint_mermaid.py` في GithubBot: فاحص أقدم يعتمد على التعبيرات النمطية (regex) مع `--fix`. يصلح الأنماط المعروفة تلقائياً، **لكنه لا يعرف الكلمات المحجوزة** ولا يحل محل هذه المهارة. الترتيب المفيد: أولاً `mermaid_lint.mjs` للتشخيص، ثم عند الحاجة `lint_mermaid.py --fix` للأنماط الجماعية، ثم الفحص مرة أخرى.
- `github-repo-care`: البروتوكول الشامل لصيانة المستودعات والنشر.
