# Bilingual-Doc-Sync — 並行言語バージョンの同期維持

## 概要と目的

2言語で運用されるドキュメントは徐々に乖離していきます。活発に編集されるバージョンが成長する一方で、もう一方のバージョンは古くなり、最終的には名ばかりの「翻訳」になってしまいます。このSkillは、同期チェックを定義された手順にし、1つの重要な事前決定を伴います。それは **「どのバージョンが主導（主言語）か？」** です。主言語のルールがないと、すべての差異がその場限りの判断になり、同期作業の再現性が失われます。

## 手順

### 1. 現状の確認

- 両方（すべて）の言語バージョンが存在するか？完全に欠落している場合 → **追いつかせる**（主言語バージョンの完全な翻訳であり、新規執筆ではない）。
- 命名規則（例: `DOCUMENT.md` + `DOCUMENT.en.md` や `_de`/`_en` サフィックス）を確認し、表記の揺れを統一する — 検索性の確保は同期の半分を占めます。

### 2. 主言語の明確化（各同期の前）

- 主言語とは、実質的に内容の編集作業が行われるバージョンです（論文ではEN、ローカルドキュメントでは母国語であることが多い）。対立が発生した場合は主言語が優先されます。
- **逆取り込みの例外:** 副言語バージョンが実証的に優れている場合（より明確な表現、修正されたエラーなど）、それを主言語バージョンに**取り込み**ます — まず逆取り込みを行い、その後に通常の同期を行います。「より美しい」表現を取り込む前に、専門的な正確性を確認してください。

### 3. 並行性の検証

まず構造、次に内容：

1. **構成の比較:** 両バージョンの章/見出しを並べて比較 — 欠落、追加、順序変更されたセクションが主な差異です。
2. **一致する構成のセクションごとの抜粋検査:** 主張、数値、参照、例が同一か？特に乖離しやすい項目: 変更履歴 (Changelog)、表、数値、文献/リンク一覧、最近編集されたセクション。
3. **翻訳不可な不変要素の検証:** コードブロック、識別子、数式、パスは両バージョンで**完全同一**でなければなりません（コードは絶対に翻訳しません）。

### 4. 解消

- 主言語の方向へ乖離を解消する（または逆取り込みの後）。
- ターゲット言語のタイポグラフィを尊重する（ドイツ語の場合は ae/oe/ue の代用表記ではなく実際のウムラウト ä ö ü ß を使用、引用符の標準規則に従う）。
- メタデータを追従させる: **両方の**バージョンでバージョン番号、日付フィールド、変更履歴の項目を更新する（変更履歴自体が最も頻繁な乖離ポイントです）。

### 5. 記録

結果を記録する（何が乖離していたか、何を取り込んだか、何を逆取り込みしたか）。
ドキュメント資産全体の定期実行として: ローテーションフレームワーク (`rotation-check`) と組み合わせる — 1回の実行につき1つのドキュメント（対）、レジストリを記憶として利用。

## 拡張: 拡張性監査（さらに言語を追加すべきか？）

既存バージョンの同期維持に加え、言語管理にはドキュメント/プロジェクトが**追加の**言語を必要としているかを問いかけることが含まれます：

1. **ブラインド翻訳ではなく適性を評価する:** ターゲット層、国際的な利用可能性、ストア/Webでの存在感、コンテンツの移動性。すべての内部ドキュメントに英語が必要なわけではありません。すべてのアプリに5つの言語が必要なわけではありません。
2. **技術的準備を確認する:** ターゲットが言語ファイル/並行バージョン（i18n構造、命名規則）に対応できているか？対応できていない場合、**それ**が最初のタスクであり、翻訳ではありません。
3. **所見を記録し、すぐに大量翻訳しない:** 具体的な翻訳タスクはプロジェクトローカルのTODOファイルに追加します。「追加言語の必要なし」も記録すべき有効な結果です。
4. **追従バージョンのQA:** 自動生成された翻訳を「完了」とする前に、主言語バージョンに対して抜き打ち検査を行う（第3節）。

## 例と応用

```text
タスク: 「論文のDE版とEN版が同期しているか確認する。」

1. 現状: paper_en.tex (主言語) + paper_de.tex が存在。
2. 構成: DEに新しいセクション 4.2 (最新のENリビジョン) が欠落。DEの 3.1 により良い証明段落がある。
3. 逆取り込み: 3.1 の表現を専門的に検証 → ENに取り込み。
4. 追従: 4.2 をDEに翻訳。表2の数字を照合 (DEに古い数値があった)。文献目録を同一化。
5. レジストリ記録: 「paper-X | 2026-07-03 | de-en-sync | 3つの乖離を解消、1つの逆取り込み | 次回のENリビジョン後に再チェック」。
```

## レッドフラグ (Red Flags)

| visual/思考 | 現実 |
| --- | --- |
| 「差異をイチから新しく翻訳すればいい」 | まず主言語と逆取り込みの有無を確認する — そうしないと優れた解決策が上書きされてしまいます。 |
| 「構成が一致しているから同期されている」 | 数値、変更履歴、参照が最初に乖離します — 深掘りした抜粋検査が必須です。 |
| 「コードのコメントも一緒に翻訳する」 | コードブロックと識別子は両バージョンで同一（英語）に保ちます。 |
| 「すべてのドキュメントを一度に同期する」 | 1回の実行につき1対（ローテーションフレームワーク）にすることで、同期の検証可能性を維持します。 |
