# フォルダ整理

## 目的と境界

すべての変更が、ローカルの規則、内容、ファイル同士の関係、またはユーザーの明示的な判断によって裏付けられる、追跡可能な保管構成を作成する。このスキルは意味に基づく整理手順であり、第二のファイル移動プログラムではなく、特定の提供元への必須の依存もない。

棚卸しや点検は読み取り専用のままとする。「このフォルダを整理して」といった明示的な依頼は、指定された範囲内での安全で可逆的な移動を許可するが、未解決の曖昧さがないことを条件とする。上書き、完全削除、範囲外への移動、内容の書き換え、または常時自動化の有効化には、別途の承認が必要である。

## 単独の核と任意の種

常に単独の核から始める。これには読み取り、書き込み、ハッシュ計算、通常のファイル操作のみが必要である。再現可能な棚卸しには [`scripts/folder_organization.py`](scripts/folder_organization.py) を使用できる。安全な既定値と上書き設定は [`config.json`](config.json) にある。スクリプトは既定では標準出力にのみ書き込む。`--out` が書き込めるのは、調査対象のルートの外に新しいファイルを作成する場合に限られ、既存の対象は上書きされない。そのログやバージョンの検出結果は、アーカイブの承認ではなく、信頼度の低い検索の手がかりである。

ライブラリ版には拡張カタログ用のフロントマターがある。対象システムがポータブルな基本フロントマター（`name`、`description`）しか受け付けない場合、[`scripts/export_portable.py`](scripts/export_portable.py) が新しい対象フォルダに独立したコピーを生成する。業務の流れとすべてのローカルの代替部品はそのまま保持される。

その後、製品名ではなく機能を検出する。既存の統合は核を改善してよいが、意味や権限を変えてはならない。

| 必要な機能 | 単独の代替手段 | 任意の検出済み種/アダプター |
|---|---|---|
| 目録、ハッシュ、計画 | 同梱の Python スクリプトまたはネイティブのファイル検索 | FolderHome の計画/受領記録 |
| 文書内容/OCR | 既存のローカル読み取りツール。なければ `unreadable/review` | doc-services または同等の抽出器 |
| クラウド/ロックに安全な操作 | 新しい状態確認を伴うネイティブ操作 | FileCommander またはプロバイダー独自のアダプター |
| 繰り返される安定したルール | 設定を提案として出力する | file-collect-sort-action または同等の自動化 |
| ヒントの再索引化 | テキスト中の目立つ CLUE マーカー | Gardener または他のローカル索引作成ツール |

Ellmos のコンポーネントは、そのため **Grounding Seeds** として扱う。その機能が利用可能で、作業に対して許可されている場合は、より強力なゲートを使用する。存在しない場合は、同じ業務の流れをヒューリスティックに、このスキルの代替部品で実行する。ローカルの読み取りツールがないという理由だけで外部へ送信してはならない。

## 手順

### 1. ルート、規則、モードを決める

- 最小の共通保管ルートを選ぶ。便宜のためにユーザー全体やクラウドのルート全体をスキャンしない。
- ルートおよびその上位の制御ファイルを読む。例として `AGENTS.md`、`CLAUDE.md`、`README.md`、`START.md`、命名規則、レジスタ、マニフェスト、ロックなど。
- モードを記録する。一度限りの意味的整理、アーカイブ保守、ログ保守、Cut-and-Clue、または繰り返し規則の準備のいずれかである。
- 既存の対象フォルダとその実際の使われ方は、作り上げた理想的な分類体系より優先される。

### 2. 内容にアクセスする前に秘密情報の方針を適用する

開く、またはハッシュを計算する前に、名前を `secret_policy.protected_name_patterns` および `config.json` の除外規則と照合する。`.env`、秘密鍵、認証情報ファイルのような保護対象のファイルは、パスとメタデータのみを記録する。その内容が modelコンテキスト、報告書、ログに入ってはならない。`--hash-all` もこの境界を解除しない。通常読めるファイル内で偶然に秘密の兆候が検出された場合は、内容の出力を止め、信号 ID のみを報告する。

ファイルがクラウド/同期ルートにあると思われる場合は、設定された `cloud_action` が適用される。既定は `localize-after-approval` である。すなわち、すべての同期ルートの外にあるローカルの対象を用意し、制限された権限を確認し、ドライランと承認を得てから、ファイルを不透明な形でコピーし、内部でハッシュを検証する。その後にのみクラウドの元のファイルを復元可能な形で置き換え、秘密ではない参照ポインターを残す。`local_secret_root` が設定されていない場合、または実行時参照が危険にさらされている場合は、ブロックする。

完全なトランザクション、ポインターモード（`control-file`、`sidecar`、`placeholder`）、ローカルのポインターマップ、ローテーションの注意点、および厳格なブロッカーは [`references/secrets-policy.md`](references/secrets-policy.md) に記載されている。秘密の疑いがあるファイルは、方針の決定が出るまで通常の振り分け、アーカイブ、Cut-and-Clue、ごみ箱から除外する。

### 3. 在庫と関係を記録する

パス、サイズ、変更日時、種類、そして妥当な範囲で SHA-256 を記録する。内容が曖昧な文書では、内容またはメタデータを読む。読めないバイナリファイルは明示的に未確定のままとする。ファイル名や拡張子だけでは、取り消しできない操作を正当化しない。

関連するファイルは一つの組として扱う。言語版、元データと書き出し、Markdown と PDF、文書とアセット、データ・スクリプト・結果、添付ファイルと主ファイル、前身と後継がこれにあたる。移動の前にリンク、マニフェスト、インクルード、コード内の参照、レジスタを確認する。

困難な在庫のための詳細な根拠と信頼度のマトリクスは [`references/heuristics.md`](references/heuristics.md) を参照する。

### 4. 目標構成と個別の判断を計画する

目標構成は、目的、既存の規則、実際のまとまりから導く。ルートは経路のための面であり、恒久的な保管場所ではない。発見物の内容が未確定の場合は、`_Sonstiges` のような一律のフォルダを作らず、`review/` または判断リストを使う。

計画された各変更には、少なくとも次を含める。

| 項目 | 内容 |
|---|---|
| 元 | 正確な相対パス、必要に応じてハッシュ |
| 先/操作 | `keep`、`move`、`rename`、`archive`、`trash-review`、`cut-and-clue`、`review` |
| 根拠 | 規則、内容、関係、またはバージョンの証拠 |
| 信頼度 | 高、中、低 |
| 副作用 | 影響を受けるリンク、組、レジスタ、または自動化 |

- **高:** 明示的なローカル規則、明確なマニフェストとの関連、または十分に裏付けられた後継の系列。
- **中:** 強い内容の一致または既存のまとまりがあるが、明示的な規則はない。
- **低:** 名前、拡張子、変更日時、または不確かな類似性のみ。自動で移動しない。

変更の前に、完全なドライランを提示する。衝突、シンボリックリンク、クラウドのロック、読めないファイル、ルート外の対象は、該当する操作をブロックする。

### 5. バージョンとログをアーカイブする

古いファイルは、系列が複数の信号で裏付けられている場合にのみ前身としてアーカイブする。信号とは、バージョンや日付の識別子、内部のバージョン表記、高い内容の重なり、適合する目的、そして明確に有効な後継である。変更日時だけでは不十分である。参照されている証拠の状態と承認済みの公開物は保持する。

ログについては、実行中のログ、監査・証拠ログ、ローテーション可能な履歴を区別する。有効なログや書き込み中のログは移動しない。古く完了したログは、ローカルの慣習に従って、またはそれがない場合は例えば `_archive/logs/<jahr>/` の下に、ハッシュと元の場所を記録してアーカイブする。圧縮は別の判断である。アーカイブは自動的に削除を意味しない。

### 6. Cut-and-Clue を適用する

ファイルに有効な内容と古くなった内容が同時に含まれる場合、盲目的に移動することも、すべてを残すことも誤りである。その場合は、有効な内容を新しい正規のファイルに **切り出し**、元の素材に、また必要に応じて問題の箇所に、状態・理由・後継を示す機械可読な **Clue** を残す。完全性を確認した後に初めて、元のファイルをアーカイブする。

マーカー、`[sic]` に関する規則、バイナリファイル、歴史の喪失を防ぐ仕組みは [`references/cut-and-clue.md`](references/cut-and-clue.md) に記載されている。`[sic]` は意図的に引用された誤りを示す。古くなったことを示すには `OUTDATED` または `SUPERSEDED` を使う。

### 7. 削除ではなく確認用ごみ箱を使う

ルート内の削除候補は、`_trash_review/<run-id>/` のような実行フォルダに移す。相対構造を保持し、`MANIFEST.md` または `RESTORE.json` に、元の場所、新しいパス、ハッシュ、理由、時刻を記録する。その中から自動的に完全削除するものはない。これにより、利用者は実行全体を確認し、後で自ら削除するか、ロールバックできる。

監視対象の受信フォルダがある場合は、自己取り込みを防ぐため、ごみ箱とアーカイブをそのスキャン範囲の外に作成する。

### 8. 実行し、証跡を残す

- 各操作の直前に、元、ハッシュ、先、先が存在しないことを再確認する。
- 決して上書きしない。衝突した場合はブロックするか、明示的に計画された新しい名前を使う。
- 実行後に対象の在庫を読み直し、ハッシュを比較し、参照内の古いパス名を検索し、影響を受けるレジスタを更新する。
- 自分で作成した空フォルダのみを削除する。すべての変更について、巻き戻し経路またはマニフェストを残す。
- ローカルの索引作成ツールがある場合は CLUE マーカーを再索引化する。ない場合は、通常の目立つテキストとして有効なままとする。

## 短い例

- `bericht_v1.md` と `bericht_v2.md`: まずは可能性のあるバージョンの系列としてのみ印を付ける。内部バージョン、内容、参照によって、`v1` を本当にアーカイブしてよいか判断する。
- `konzept.md` には有効な規則と古くなった節が含まれる: 有効な実質部分を新しい正規のファイルに完全に移し、バイト単位で同一の原本を保全し、後継を示す Clue/サイドカーを作成する。
- 同期ルート内の `.env`: 開かず、報告書にコピーしない。方針計画を作成する。`local_secret_root` が確認でき、承認があり、実行時の安全な切り替えが行われない限り、ファイルを変更しない。

## 学習と自動化

ユーザーの修正は規則の候補として収集し、決して黙って規則に昇格させない。あるパターンが繰り返し確認され、矛盾がなく、明確に範囲が限定されて初めて、繰り返し実行される自動化を提案する。新規または変更された自動化には、改めてドライランと承認が必要である。

## 完了報告

在庫、実行した操作とブロックした操作、アーカイブとごみ箱、Cut-and-Clue の後継、未解決の判断に加えて、すべての秘密情報の候補はパス/信号 ID のみで、その方針の状態、ブロックまたは承認されたクラウド退避、ポインターモード、読み戻しとともに報告する。値、ローカルの秘密情報のパス、機微な文脈の行は決して再掲しない。

元の在庫、実行された操作とブロックされた操作、アーカイブとごみ箱のパス、Cut-and-Clue の後継、更新された参照、ハッシュと読み戻しの結果、未解決の判断、提案された繰り返しルールを報告する。計画は実行された整理ではない。
