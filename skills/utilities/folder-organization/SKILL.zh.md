# 文件夹整理

## 目标与边界

生成一个可追溯的存储结构，使每一项变更都有本地规则、内容、文件关系或用户明确决定作为依据。本技能是语义化整理协议，而不是第二个文件移动程序，也不强制绑定任何供应商。

盘点或检查保持只读。明确的请求（如“整理这个文件夹”）授权在指定范围内进行安全、可逆的移动，前提是不存在未解决的歧义。覆盖、永久删除、移出范围、改写内容或启用常驻自动化，都需要单独授权。

## 独立核心与可选种子

始终从独立核心开始。它只需要读取、写入、哈希和普通文件操作。为了可复现的盘点，提供 [`scripts/folder_organization.py`](scripts/folder_organization.py)；安全默认值与覆盖选项见 [`config.json`](config.json)。脚本默认只写入标准输出。`--out` 只允许在被检查根目录之外创建一个新文件；已存在的目标不会被覆盖。其日志与版本发现结果只是低置信度的搜索线索，而不是归档许可。

库内版本包含扩展的目录（catalog）前置元数据。如果目标系统只接受可移植的基础前置元数据（`name`、`description`），[`scripts/export_portable.py`](scripts/export_portable.py) 会在新的目标文件夹中生成一个独立副本。其业务流程和所有本地替代组件都会完整保留。

之后应发现能力，而不是品牌名称。已有的集成可以改进核心，但不得改变其含义或权限：

| 所需能力 | 独立替代方案 | 可选的已检测种子/适配器 |
|---|---|---|
| 清单、哈希、计划 | 随附的 Python 脚本或原生文件搜索 | FolderHome 计划/回执 |
| 文档内容/OCR | 现有本地读取器；否则 `unreadable/review` | doc-services 或同等提取器 |
| 云/锁定安全操作 | 带新鲜状态检查的原生操作 | FileCommander 或服务商自有适配器 |
| 可重复的稳定规则 | 将配置作为建议输出 | file-collect-sort-action 或同等自动化 |
| 重新索引线索 | 显眼的 CLUE 标记文本 | Gardener 或其他本地索引器 |

因此，Ellmos 组件是**基础种子（Grounding Seeds）**：当其能力可用且已获授权用于该任务时，使用其更强的门控。若缺失，则使用本技能的替代组件，以启发式方式执行相同的业务流程。不能仅因缺少本地读取器就进行外部传输。

## 操作步骤

### 1. 确定根目录、规则与模式

- 选择最小的共同存储根目录；不要为图方便扫描整个用户或云根目录。
- 读取根目录及其上级目录中的控制文件，例如 `AGENTS.md`、`CLAUDE.md`、`README.md`、`START.md`、命名规则、登记册、清单和锁文件。
- 记录模式：一次性语义整理、归档维护、日志维护、Cut-and-Clue，或准备可重复规则。
- 已有的目标文件夹及其实际用途，比虚构的理想分类体系更有分量。

### 2. 在任何内容访问前执行机密策略

在打开或哈希任何文件之前，先将文件名与 `secret_policy.protected_name_patterns` 及 `config.json` 中的排除项进行比对。受保护文件（如 `.env`、私钥或凭据文件）只能记录路径与元数据；其内容不得进入模型上下文、报告或日志。`--hash-all` 不会取消这一边界。若在通常可读的文件中偶然检测到机密信号，应停止输出内容，只报告信号 ID。

若文件可能位于云端/同步根目录中，则适用已配置的 `cloud_action`。默认值为 `localize-after-approval`：确认存在位于所有同步根目录之外的本地目标并设置了严格权限，先试运行并获得授权，以不透明方式复制文件并通过内部哈希校验，然后再以可恢复的方式替换云端源文件，并留下一个非机密指针。若未设置 `local_secret_root`，或运行时引用存在风险，则阻止操作。

完整事务、指针模式（`control-file`、`sidecar`、`placeholder`）、本地指针映射、轮换提示及硬阻断条件，见 [`references/secrets-policy.md`](references/secrets-policy.md)。在策略决定之前，疑似机密文件应排除在常规排序、归档、Cut-and-Clue 与回收站之外。

### 3. 盘点并记录关系

记录路径、大小、修改时间、类型，并在合理范围内记录 SHA-256。对于含义不明确的文档，读取内容或元数据。无法读取的二进制文件须明确标记为未确定；仅凭文件名和扩展名不足以证明可以执行不可逆操作。

将相关文件视为一个集合：语言版本、源文件/导出文件、Markdown/PDF、文档/资源、数据/脚本/结果、附件/主文件，以及前身/后继版本。移动之前，检查链接、清单、包含项、代码引用和登记册。

对于复杂存量的详细证据与置信度矩阵，阅读 [`references/heuristics.md`](references/heuristics.md)。

### 4. 规划目标结构与单项决定

目标结构应从用途、现有规则和实际聚类中推导。根目录是路由区，而不是长期存放区。若某项发现的内容尚不明确，不要创建 `_Sonstiges` 之类的笼统文件夹；应改用 `review/` 或决定清单。

每项计划变更至少包含：

| 字段 | 内容 |
|---|---|
| 源 | 精确的相对路径，可选哈希 |
| 目标/动作 | `keep`、`move`、`rename`、`archive`、`trash-review`、`cut-and-clue`、`review` |
| 理由 | 规则、内容、关系或版本依据 |
| 置信度 | 高、中或低 |
| 副作用 | 受影响的链接、集合、登记册或自动化 |

- **高：** 明确的本地规则、清晰的清单关联或有充分依据的后继序列。
- **中：** 内容高度吻合或属于既有聚类，但没有明确规则。
- **低：** 仅依据名称、扩展名、修改时间或不确定的相似性。不得自动移动。

在任何变更之前，提供完整的试运行结果。冲突、符号链接、云端锁、无法读取的文件以及根目录之外的目标，都会阻止对应动作。

### 5. 归档版本与日志

只有当序列有多个信号支持时，才可将旧文件归档为前身版本：版本或日期标识、内部版本信息、高度的内容重叠、一致的用途，以及一个明确有效的后继版本。仅凭修改时间不足以作为依据。被引用的证据版本和已批准发布的版本应予保留。

对于日志，区分活动运行日志、审计/证据日志和可轮转的历史记录。不要移动活动中或仍在写入的日志。旧的已关闭日志应依据本地约定归档（若无约定，例如放在 `_archive/logs/<jahr>/` 下），并记录哈希与原始位置。压缩是单独的决定；归档并不自动等同于删除。

### 6. 应用 Cut-and-Clue

若文件同时包含有效内容与过时内容，那么盲目移动和全部保留都是错误的。此时应将有效内容**切出**，写入新的规范文件，并在旧材料中（必要时直接在问题位置）留下一个机器可读的 **Clue**，说明状态、原因和后继文件。只有在完整性检查通过后，才归档原始文件。

标记、`[sic]` 的规则、二进制文件处理以及防止历史丢失的保护措施，见 [`references/cut-and-clue.md`](references/cut-and-clue.md)。`[sic]` 用于标记有意引用的错误；对于过时内容，应使用 `OUTDATED` 或 `SUPERSEDED`。

### 7. 使用待审回收站代替删除

将根目录内的删除候选项移入一个运行文件夹，例如 `_trash_review/<run-id>/`。保留相对结构，并写入 `MANIFEST.md` 或 `RESTORE.json`，记录来源、新路径、哈希、原因和时间。不得据此自动永久删除任何内容。这样用户可以审查整个运行，之后自行删除或回滚。

若存在受监控的输入文件夹，应将回收站和归档放在其扫描范围之外，以避免自我馈送。

### 8. 执行并留存证据

- 每一动作执行前，重新检查源、哈希、目标以及目标不存在的状态。
- 绝不覆盖；遇到冲突时阻止，或使用明确计划的新名称。
- 运行结束后，读取目标的实际状态，比对哈希，搜索引用中的旧路径名，并更新受影响的登记册。
- 只删除自己创建的空文件夹。每一次变更都要保留回退路径或清单。
- 若有本地索引器，则重新索引 CLUE 标记；若没有，它们仍作为普通、显眼的文本发挥作用。

## 简短示例

- `bericht_v1.md` 与 `bericht_v2.md`：首先仅将其标记为可能的版本序列。只有在内部版本、内容和引用共同确定 `v1` 确实可以归档之后，才能执行归档。
- `konzept.md` 同时包含有效规则与过时章节：将全部有效内容完整迁入新的规范文件，备份字节级一致的原始文件，并创建包含后继信息的 Clue/侧车文件。
- 同步根目录中的 `.env`：不要打开它，也不要将其内容复制到报告中。生成策略计划；若没有已确认的 `local_secret_root`、授权及安全的运行时切换，则不得修改该文件。

## 学习与自动化

将用户的更正收集为规则候选项，绝不可静默升级为正式规则。只有当某一模式被反复确认、无冲突且范围明确时，才可建议将其设为可重复的自动化。每一项新的或已修改的自动化，仍需重新经过试运行并获得授权。

## 结案报告

除盘点、动作、归档、回收站、Cut-and-Clue 后继文件以及未决决定之外，还需仅通过路径/信号 ID 列出所有机密候选项、其策略状态、已阻止或已授权的云端迁出、指针模式以及回读结果。切勿输出任何值、本地机密路径或敏感上下文行。

报告应说明：初始存量、已执行与被阻止的动作、归档与回收站路径、Cut-and-Clue 后继文件、已更新的引用、哈希/回读结果、未决决定，以及建议的可重复规则。规划不等于已完成的整理。

## 相关技能

- 整理/维护：适用于会话收尾、登记册维护和临时项目文件。
