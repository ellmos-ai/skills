# Decision-Briefing — Проработка множества решений по одной теме

> Накопившиеся открытые решения превращаются в пронумерованный брифинг с рекомендациями, на которые пользователь может отвечать с молниеносной скоростью отдельными буквами — по одному или пакетом.

---

## Когда использовать?

**Всегда, как только накопилось несколько открытых решений** — независимо от темы. Типичные ситуации:

- Накопилось много нерешенных вопросов в одной области/теме
- Документ (план, список TODO, концепт) содержит несколько нерешенных пунктов
- В ходе разговора накопилось несколько вопросов, требующих решения
- У самого агента есть несколько вопросов к пользователю — объедините их в брифинг вместо того, чтобы задавать по одному
- Пользователь хочет быстро и на надежной основе закрыть открытые пункты

**Ключевые слова для запуска:** открытые решения, сессия решений, брифинг, проработать решения, пройти по решениям, давай все решим

**Область применения:** [decide](../decide/SKILL.en.md) предоставляет фреймворки для ОДНОГО вопроса. `decision-briefing` координирует проработку МНОГИХ решений по одной теме — и применяет `decide` к сложным индивидуальным случаям.

---

## Основной UX

Сердцем этого навыка является формат брифинга. Каждое решение представляется таким образом, чтобы ответ требовал всего одной буквы:

- **Нумерация:** `[E01]`, `[E02]`, … — стабильные ссылки на протяжении всей сессии
- **Короткий вопрос** + 1–2 предложения контекста
- **Варианты в виде букв** A/B/C/D (2–4 варианта, больше только при необходимости)
- **Отмеченная рекомендация** с обоснованием в одно предложение (например, `→ Recommendation: A — because …`)
- Опционально: примечание о последствиях (что следует из выбора)

**Форматы ответов пользователя:**

```
Single:    "E01: A"  or  "1A"
Batch:     "1A 2C 3B"  or  "E01: A, E02: C, E03: B"
Deepen:    "E02: more info"  or  "2?"
Defer:     "E03: later"
```

## Рабочий процесс и порядок действий

```
Topic + decisions at hand
     |
     v
Phase 1: CAPTURE & INVENTORY
     |
     v
Phase 2: PREPARE THE BRIEFING
     |
     v
Phase 3: DECISION SESSION
     |
     v
Phase 4: RECORD & WRITE BACK
```

### Фаза 1: Сбор и инвентаризация

Источники: то, что называет пользователь, имеющийся документ или контекст беседы. Без сканирования всей системы — только то, что уже имеется.

1. Перечислить все открытые решения (по одной строке на каждое: краткий заголовок)
2. Выявить и объединить **дубликаты** (один и тот же вопрос, сформулированный несколько раз)
3. Отметить **зависимости** ("E04 зависит от E01")
4. Установить **порядок**: сначала блокирующие (решения, от которых зависят другие), затем по срочности
5. Показать список пользователю для подтверждения ("Все ли я учел? Ничего не упущено?")

### Фаза 2: Подготовка брифинга

Для каждого решения:

```
[E01] <Short question>
  Context: <1-2 sentences: Why is this up? What depends on it?>
  A) <Option>
  B) <Option>
  C) <Option>
  → Recommendation: <letter> — <one-sentence rationale>
  (optional) Consequence: <what follows from the choice / next action>
```

Правила хороших вариантов:

- Варианты должны быть взаимоисключающими и охватывать весь спектр
- Если полезно, включите вариант "сохранить статус-кво" или "отложить"
- Рекомендация обосновывается прозрачно — без скрытых навязываний
- Если факты неясны: сначала уточните (или отметьте как открытый вопрос), не угадывайте

### Фаза 3: Сессия решений

1. Представить брифинг — по одному решению в сообщении или все сразу пакетом; если решений >5, использовать блоки по 3–5
2. Принимать ответы буквами и подтверждать их
3. При ответе "подробнее": углубить решение (инструментарий методов ниже)
4. Для сложных индивидуальных случаев (много критериев, высокие ставки): эскалировать в навык [decide](../decide/SKILL.en.md) (взвешенная оценка, анализ сценариев)
5. Явно переносить отложенные решения как открытые — никогда не терять их молча

### Фаза 4: Фиксация и запись обратно

1. Создать **таблицу результатов**:

```
| No.  | Decision            | Chosen | Status   |
|------|---------------------|--------|----------|
| E01  | <short title>       | A      | decided  |
| E02  | <short title>       | C      | decided  |
| E03  | <short title>       | —      | deferred |
```

2. Записать принятые решения обратно в **исходные документы / файлы TODO** — в месте открытого вопроса, например:

```
DECISION: <question>
  → DECIDED 2026-06-13: Option A (<short form>)
  → Next action: <if the decision implies a follow-up action>
```

3. Сохранять **отложенные пункты явно открытыми** (в исходном документе или списке TODO), чтобы они снова появились в следующем брифинге

## Пример и применение

Тема: перезапуск сайта клуба — 3 открытых решения из плана проекта.

```
[E01] Which system for the new website?
  Context: Current site is hand-maintained HTML; 2 people will maintain content in the future.
  A) Static site generator (fast, secure, maintained via Git)
  B) Classic CMS with admin interface
  C) Hosted website builder
  → Recommendation: B — two non-technical editors need an interface, not Git.

[E02] How is it hosted?
  Context: Budget ~10 EUR/month, no dedicated admin in the club.
  A) Shared hosting with the current provider
  B) Small dedicated VPS
  C) Managed hosting matching the chosen system
  → Recommendation: C — least maintenance effort without an admin; consequence: depends on E01.

[E03] When does the new site go live?
  Context: Content is 60% migrated; club anniversary in 3 months.
  A) Immediately as a soft launch (rest follows)
  B) After complete content migration
  C) On the anniversary as the deadline
  → Recommendation: A — reversible and yields early feedback; final content follows.
```

Пользователь отвечает пакетом: **"1B 2C 3A"** → таблица результатов, затем эти три решения отмечаются как DECIDED в плане проекта.

## Инструментарий методов (для ответов "подробнее" и углубления)

| Метод | Когда | Краткое описание |
|--------|------|---------|
| **Матрица за и против** | 2–3 варианта, быстрое сравнение | Оценка всех вариантов бок о бок |
| **Взвешенная оценка (Weighted scoring)** | Множество критериев | Взвешенные критерии, баллы по вариантам (по возможности количественно) |
| **Мышление второго порядка** | Неясные ставки / последствия | Каковы последствия последствий? |
| **Премортем (Premortem)** | Рискованное решение | "Проект провалился — почему?" Заранее найти слабые места |
| **Метод 10/10/10** | Эмоциональные / временные искажения | Как выглядит решение через 10 минут / 10 месяцев / 10 лет? |

## Принципы работы

- **Никогда не навязывать решения:** предоставлять информацию, прозрачно обосновывать рекомендацию — решение принимает пользователь
- **Выявление когнитивных искажений:** называть ошибки мышления при их проявлении (предвзятость подтверждения, невозвратные затраты)
- **Учитывать обратимость:** быстро принимать обратимые решения; к окончательным относиться более тщательно
- **Учитывать дефицит времени:** быстрые решения требуют простых методов — не каждый вопрос заслуживает взвешенного скорингового анализа

## Область применения и синергия

| Функция | `decide` | `decision-briefing` |
|---|---|---|
| Структурирование одиночного решения с помощью фреймворка | ✓ | — |
| Инвентаризация множества решений по одной теме | — | ✓ |
| Пронумерованный брифинг с вариантами A/B/C | — | ✓ |
| Пакетные ответы ("1A 2C 3B") | — | ✓ |
| Запись обратно в исходные документы | — | ✓ |

**Синергия:** Для сложных индивидуальных случаев внутри сессии `decision-briefing` применяет фреймворки из `decide` (взвешенная оценка, анализ сценариев). Для более широкого мыслительного процесса до этого (анализ → генерация идей → решение) см. [structured-thinking](../structured-thinking/SKILL.en.md).
