# decision-shot

> Анализ готов. Теперь нужна не вторая выкладка, а суть плюс путь назад к полной версии.

## Когда использовать

- Решение (или тесно связанная группа, например несколько подвопросов одной темы) уже продумано — в чате, в тикете, по фреймворку `decide` или на фазе 2 `decision-briefing` — и теперь его нужно за секунды донести до кого-то (пользователя, другого агента, передаточного документа).
- Триггер-слова: «коротко с плюсами и минусами», «executive summary», «краткий контекст», «тезисы для разговора», «дай это компактно с рекомендацией», `/decision-shot`.
- **Не** при нескольких ещё открытых, нерешённых пунктах, которые пользователь должен подтвердить подряд или пакетом по буквам, — это [decision-briefing](../decision-briefing/SKILL.md). **Не** для выработки решения с нуля — это [decide](../decide/SKILL.md). decision-shot — чисто ПРЕЗЕНТАЦИЯ уже имеющегося анализа.

## Разграничение (кратко)

| Навык | Что делает | Когда завершён |
|---|---|---|
| `decide` | Прорабатывает ОДНО решение с помощью фреймворка (матрица плюсов/минусов, взвешенная оценка, дерево решений, ...) | Анализ ещё не готов |
| `decision-briefing` | Собирает МНОГО открытых решений по теме, представляет их пакетом A/B/C/D и принимает ответы буквами | Несколько пунктов ещё не решены |
| `decision-shot` | Сжимает ОДИН готовый анализ (откуда бы он ни взялся) до executive-формы со ссылкой на полную версию | Анализ уже есть, нужна только подача |
| `knappform` | Общий модификатор стиля ответов для КАЖДОГО ответа сессии | На всю сессию, независимо от темы |
| `paveman` | Детерминированно сокращает существующие ПРОЗАИЧЕСКИЕ ФАЙЛЫ (файлы правил/памяти) | Сокращает файл, а не вывод в чате |

`decision-shot` не конкурирует ни с одним из четырёх — это ФОРМАТ, который применяется после `decide` или рядом с `decision-briefing`, как только суть нужно передать дальше. Сокращённый языковой стиль ориентирован на `knappform`/`paveman` (полный список сокращений — там), но здесь последовательно применяется к фиксированному пятичастному формату.

## Формат (обязательный, пять частей)

```
## <Entscheidungstitel>

**Kontext:** <2-3 Zeilen -- worum es geht, warum jetzt, was auf dem Spiel steht>

**<Option A>**
+ <staerkstes Pro-Argument>
+ <zweites Pro-Argument, nur falls es traegt>
- <staerkstes Contra-Argument>

**<Option B>**
+ <Pro>
- <Contra>
- <Contra>

**Talking Points:**
- <Punkt, der im Gespraech/in einer Mail sofort zieht>
- <Punkt, der einen typischen Einwand vorwegnimmt>

**Empfehlung:** <Option> -- <ein Satz Begruendung, keine Wiederholung der Pro-Liste>

**Vollanalyse:** <Pfad oder Link -- Ticket-Datei, Dokument, Chat-Referenz>
```

## Правила

- **Тексты для пользователя без технических номеров и сокращений (форма «я» на разговорном языке):** в видимом для человека тексте (заголовок, контекст, варианты, тезисы для разговора, рекомендация) **не должно быть** внутренних сокращений, номеров тикетов (`T-...`), идентификаторов D или относительных путей к файлам. Контекст описывает ситуацию и запланированное действие в форме «я» («Я предлагаю...»). Технические ссылки (ID тикета, точный путь к файлу) стоят только в завершающей строке `**Vollanalyse:**` или в таблице ссылок.
- **Строки — это бюджет, а не цель.** 2-3 строки контекста, 2-4 пункта на каждый вариант, 2-3 тезиса для разговора, 1 предложение рекомендации — лишнее удаляется, а не «сокращается, но сохраняется». Если вариант не умещается в 4 пункта, он относится не к этому навыку, а к полному анализу.
- **Сокращённый стиль как в `knappform`/`paveman`:** без слов-наполнителей, без клише и уходов от ответа. Отрицания (`nicht`, `nie`, `kein`, `nur`, `außer`) не трогаем — их удаление меняет смысл на противоположный.
- **Плюсы/минусы — это пункты, а не предложения.** `+`/`-` как префикс, одна мысль на строку, без дополнительных уточнений.
- **Тезисы для разговора — коммуникативные, а не аналитические.** Они отвечают на вопрос «что я скажу, если меня спросят», а не «что написано в анализе». Дублирование списка плюсов/минусов означает, что сжатие ещё не завершено.
- **Рекомендация обосновывает себя в одном предложении.** Без повторения списка плюсов и без «см. выше» — одно предложение должно выдерживать вес и без остального блока.
- **Ссылка/путь на полный анализ обязательны.** decision-shot не заменяет анализ, он лишь делает его быстро находимым. Если осязаемого источника нет (решение возникло только устно в чате, без документа), назовите связь с чатом/сессией максимально конкретно (например, «эта сессия, ответ на F4»), а не оставляйте поле пустым.
- **Несколько связанных решений** (группа, например несколько подвопросов одной темы): один блок на решение, разделённые `---`, общий контекст — один раз в начале, только если он действительно относится ко всем.

### Штамп сессии для сохранённых decision-shot

Если decision-shot сохраняется как важный новый постоянный артефакт, файл завершается так:

`session: <session-id> | <agent>@<host> | YYYY-MM-DD`

Идентификатор сессии берётся сначала из явного параметра времени выполнения/CLI, затем из авторитетного окружения провайдера или хука; если нет ни того, ни другого, ставится `unbekannt`. Значения никогда не угадываются. Субагенты используют идентификатор родительской сессии. Обычный чат, источники, политики, `CLAUDE.md`, README и старые файлы не штампуются и не дополняются штампами задним числом.

## Пример

```
## Wo laeuft der naechtliche Backup-Job?

**Kontext:** Ich beobachte wiederholte Ausfälle auf dem Laptop, weil das Gerät nachts
schläft. Ich schlage vor, den Job auf den Mac Studio umzuziehen, der rund um die Uhr läuft.

**Laptop (Status quo)**
+ Keine Netzwerkabhaengigkeit
- Job faellt regelmaessig aus, wenn das Geraet schlaeft
- Kein zentraler Log-Ueberblick

**Mac Studio**
+ Laeuft 24/7, keine Ausfaelle durch Schlafmodus
+ Zentrale Logs an einem Ort
- Braucht funktionierendes Tailscale/SSH als Voraussetzung

**Talking Points:**
- "Der Ausfall ist kein Bug im Skript, sondern eine Standortfrage."
- "Tailscale laeuft schon fuer andere Jobs stabil -- kein neues Risiko."

**Empfehlung:** Mac Studio -- einzige Option ohne den bekannten Schlafmodus-
Ausfall, und die Abhaengigkeit (Tailscale) ist bereits im Betrieb bewaehrt.

**Vollanalyse:** `.SYNC/MAC_STUDIO_COMPUTE_HANDOFF.md`, Abschnitt "Backup-Jobs" (Ticket T-20260620-42)
```
