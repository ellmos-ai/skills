# Итеративный выбор пакетов

Сокращать большие наборы для выбора с помощью нескольких грубых решений, не отсеивая невыбранных кандидатов преждевременно.

## Основной принцип

1. Зафиксировать всех кандидатов как общий пул и однозначно их назвать.
2. По желанию определить тематические лужи и отнести каждого кандидата ровно к одной основной луже.
3. Последовательно применять нужные фильтры глобально или внутри отдельных луж и хранить их совпадения отдельно.
4. Внутри каждой активной лужи перемешивать и по умолчанию формировать пакеты по пять кандидатов.
5. Однозначно пометить пакеты первого раунда по лужам с помощью `THEMA-A`, `THEMA-B` …
6. Позволить пользователю выбирать целые пакеты.
7. Выбранные пакеты изъять из открытого пула и передать следующему действию.
8. Вернуть кандидатов из невыбранных пакетов в их соответствующие лужи.
9. Сохранить лужи и фильтры, перемешивать каждую лужу отдельно и использовать пометки с черточками.
10. Продолжать последующие раунды, пока пользователь не остановит процесс или пул не опустеет.

Последний пакет может содержать меньше пяти кандидатов. Невыбранные пакеты означают «пока открыто», а не «отклонено».

## Рабочий процесс

### 1. Подготовка пула

- Удалить дубликаты по стабильным именам или идентификаторам.
- Исключить уже выбранных или завершённых кандидатов.
- Пометить заблокированных кандидатов, но не удалять их молча.
- Назвать количество кандидатов исходного пула.

### 2. Формирование тематических луж

Тематическая лужа — это обособленная часть пула. Кандидаты из разных луж не перемешиваются друг с другом.

- Использовать этот метод только тогда, когда пользователь требует тематические лужи или когда тематическое разделение явно разумно.
- Документировать лужи со стабильным ID, названием, правилом отнесения и количеством кандидатов.
- Выводить лужи из указаний пользователя, существующих категорий или прослеживаемых признаков.
- Прозрачно показывать автоматически выведенные назначения до первого последующего действия.
- По умолчанию относить каждого кандидата ровно к одной основной луже; не создавать скрытых дубликатов в нескольких лужах.
- Неоднозначных кандидатов держать в `UNZU — Unzugeordnet`, пока назначение не определено.
- Лужу с меньше чем пятью кандидатами выдавать как малый пакет; никогда не дополнять её другой темой.
- Фильтры могут действовать глобально для всех луж или локально для названной лужи.
- Отфильтрованные кандидаты сохраняют своё назначение к луже, чтобы при повторной активации вернуться на правильное место.
- При разделении, объединении или переименовании лужи сбрасывать и заново формировать только её затронутые пакеты.

Пример:

```text
DEV  | Entwicklung     | 12 Kandidaten | DEV-A, DEV-B, DEV-C
MED  | Medien          |  7 Kandidaten | MED-A, MED-B
UNZU | Unzugeordnet    |  2 Kandidaten | UNZU-A
```

В последующих раундах обозначать глубину раунда буквой пакета: `DEV-A′`, `MED-B″`.

### 3. Применение ступеней фильтрации

- Выполнять фильтры необязательно и в порядке, названном пользователем.
- Протоколировать каждый фильтр со стабильным ID, режимом, правилом и количеством совпадений.
- Выполнять текстовые сравнения по умолчанию без учёта регистра.
- `exclude` удаляет совпадения только из активного пула и помещает их в фильтр-пул.
- `include` оставляет в активном пуле только совпадения; несовпадения переходят в фильтр-пул.
- Если режим не указан, а пользователь говорит, что пул нужно отфильтровать или очистить, использовать `exclude` и назвать это допущение.
- После каждой ступени выводить входной размер, количество совпадений и оставшийся размер.
- Отфильтрованных кандидатов никогда не удалять и не помечать как отклонённых; пользователь может позже отключить отдельные фильтры.

Пример:

```text
F1 | exclude | Name enthält "aws"         | 13 Treffer
F2 | exclude | Name enthält "hyperframes" | 8 Treffer
Aktiver Pool: 44 | Filterpool: 21
```

Если фильтр меняется, сбросить все прежние пакеты активного пула и только потом перемешивать заново.

### 4. Формирование раунда

- Действительно перемешивать кандидатов; не просто переименовывать прежнюю структуру пакетов.
- По возможности использовать пять кандидатов в пакете.
- Перемешивать только кандидатов одной и той же тематической лужи.
- Не дублировать и не терять кандидатов.
- Для зависимых по существу кандидатов отмечать зависимость, а не замалчивать её.

Формат вывода:

```text
Bündel DEV-A: dev-1, dev-2, dev-3, dev-4, dev-5
Bündel MED-A: media-1, media-2, media-3
```

Без тематических луж по-прежнему использовать простые пометки `A`, `B`, `C` …

### 5. Обработка выбора

- Принимать ответы вида `A, D und F`.
- Перед последующим действием полностью назвать входящих в выбор кандидатов.
- Проверять необходимые блокировки, предпосылки или пробные прогоны для каждого кандидата.
- Протоколировать успешных кандидатов как выбранных или завершённых.
- Вернуть заблокированных или неуспешных кандидатов в остаточный пул.

### 6. Повторная упаковка остатка

- Окончательно удалять только фактически успешных кандидатов.
- Все остальные кандидаты возвращать в прежние лужи и перемешивать там отдельно.
- Перед каждым новым перемешиванием заново применять активные фильтры к остаточному пулу.
- Обозначать следующий раунд пометками с черточками: `DEV-A′`, затем `DEV-A″` и так далее.
- Называть общий пул, фильтр-пул, размер активного пула и размер каждой лужи.

## Правила защиты

- Невыбор никогда не интерпретировать как окончательное отклонение.
- Совпадения фильтра никогда не отбрасывать молча; они остаются доступными из фильтр-пула.
- Границы луж при перемешивании никогда не пересекать.
- При повторном распределении не дублировать кандидатов и не переносить их между лужами, пока пользователь не меняет разделение.
- Не терять кандидатов из-за неудачной комбинации пакетов.
- Не навязывать заблокированных кандидатов; они остаются открытыми.
- При необратимых или рискованных последующих действиях сначала подтверждать каждого кандидата отдельно.
- При необходимости документировать воспроизводимый ключ перемешивания; в остальных случаях достаточно прослеживаемого нового распределения.
- Метод уменьшает сложность выбора, но не заменяет предметную оценку отдельных кандидатов.

## Разграничение

- `decide` оценивает конкретное решение с помощью критериев и фреймворков.
- `decision-briefing` координирует несколько различных вопросов решения.
- `iterative-bundle-selection` сокращает большой однородный пул кандидатов с помощью повторного группового выбора и перемешивания.

## Завершение

Процесс заканчивается, когда пул пуст, пользователь явно останавливает его или остались только кандидаты, которым нужно индивидуальное решение. Затем выдать краткий итог с выбранными, открытыми и заблокированными кандидатами.
