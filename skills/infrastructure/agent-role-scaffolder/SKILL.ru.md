## Назначение

В этой экосистеме уже есть зрелое семейство навыков оркестрации
(`model-strategy`, `swarm-operations`, `orchestrator`, `choose-your-orchestrator`,
`agents-bridge`), но **ни один из них не отвечает на вопрос «как правильно создать новую роль».** Этот пробел
закрывает `agent-role-scaffolder`. Он не дублирует указанные навыки, а **направляет к ним**, когда нужны
распределение нагрузки, паттерн оркестрации или межпровайдерные сообщения.

**Происхождение:** решение пользователя M5 из тикета `T-20260825-935905816`
(полный обзор маркетплейса): вердикт (b) — собственные знания о построении агентов
существовали, но не были формализованы. Официальный плагин Claude Code
`agent-sdk-dev` (claude-plugins-official, Apache-2.0) послужил
**структурным образцом**: командный файл scaffolding плюс два
тематических верификатора-субагента с чек-листом и форматом отчёта PASS/PASS-WITH-WARNINGS/FAIL.
Перенята **форма** (каталог вопросов для каркаса → сборка → чек-лист верификации со структурированным
отчётом), но не текст и не предмет: тот плагин собирает простые приложения Claude Agent SDK (Python/TypeScript),
а этот навык собирает **собственные роли агентов ellmos** (определения субагентов и
Companion-Worker). Оригинал НЕ установлен; он лежит в локальном кэше маркетплейса только для чтения и
использовался только для чтения (`.PLUGINS/CLAUDE.md` правило 5: идеи свободно, формулировки — нет). Запись в реестре:
`.AI/.PLUGINS/PLUGIN-REGISTER.md`, статус `zitiert`.

## Два пути построения — оба относятся сюда

В экосистеме ellmos новые роли возникают двумя структурно различными путями, которые нельзя путать (аналогично
разделению TS/Python в плагине-образце, но здесь по реальной системной границе):

| | **Нативный субагент** | **Companion-Worker** |
|---|---|---|
| Что создаётся | постоянное определение роли (`~/.claude/agents/<name>.md`, запускается инструментом `Agent`) | экземпляр с ad-hoc именем, повторно используемый через `SendMessage` для ОДНОЙ серии задач |
| Срок жизни | постоянный, повторно используется между сессиями | на время серии тикетов/тем, затем уничтожается |
| Примеры в наличии | `ati-agent`, `bueroassistent`, `versicherungs-agent`, `gesundheitsassistent`, `persoenlicher-assistent`, `production`, `research-agent`, `reflection-agent`, `test-agent`, `entwickler-agent` | сама эта модель сессии (напр. `skillcreator-bau`, `policyreg-decisions`, `workflowhooker-ausbau` — именованные Worker в системе тикетов) |
| Слой жизненного цикла | реестр агентов Claude Code | **COMA** (`.MODULES/.ORCHESTRATION/coma`) — если запускается между процессами, а не только внутри инструмента |
| Инструкция по построению здесь | `references/subagent-role-scaffold.md` | `references/companion-worker-scaffold.md` |

**Эмпирическое правило:** если способности нужно постоянное, многократно используемое имя с фиксированным
описанием триггера (напр. «всегда, когда речь идёт о налоговых документах») → нативный субагент. Если это ограниченная,
но тематически связанная серия задач, которую координатор делегирует прямо сейчас (цепочка тикетов, смена темы) →
Companion-Worker.

## Порядок действий

1. **Выбрать путь построения** (таблица выше) — в случае сомнений спросить пользователя, а не угадывать.
2. **Пройти вопросы каркаса** (см. соответствующий `references/*.md`) — как и в плагине-образце, последовательно, а не все сразу:
   назначение/триггер, потребность в инструментах (`Tools:`), выбор модели (→ **шаг 3**), потребность в координации
   (агент-босс с экспертами или отдельная роль?).
3. **Выбор модели здесь НЕ принимается — делегировать `model-strategy`.**
   Выбор по баллам, делегирование между агентами, связка советника, триггеры эскалации там уже решены;
   здесь только ссылка. Эмпирическое правило из существующих: субагенты **не** наследуют основную модель
   по умолчанию (см. память обратной связи `feedback_subagenten_modellstaffelung`).
4. **Проверить паттерн оркестрации**, если новая роль будет работать вместе с несколькими другими — `choose-your-orchestrator`
   выбирает паттерн, `swarm-operations` даёт 5 базовых паттернов + 2 режима, `orchestrator` — протокол
   декомпозиции/делегирования/приёмки.
5. **Соблюдать конвенции команды и обмена сообщениями** (`references/
   model-staffing-and-messaging.md`): `SendMessage` для обмена
   между агентами, захват тикета по имени файла при делегировании тикета, «ссылаться, а не повторять» при постановке задачи
   (центральные правила не пересказывать в промпте, только специфику задачи).
6. **Верифицировать** — выполнить подходящий чек-лист в выбранном файле `references/*.md`, составить отчёт
   в формате `PASS / PASS MIT WARNUNGEN / FAIL` (структура ниже).
7. **По необходимости занести в каталог** — постоянная новая роль попадает в подходящий реестр
   (`~/.claude/agents/`, при необходимости объединение в плагин); Companion-Worker не нуждается в записи в реестре, только в чёткой
   первой передаче задачи.

## Формат отчёта верификации (для обоих путей построения)

Структура намеренно перенята из плагина-образца (форма, не формулировки) — четыре раздела, кратко:

- **Статус:** PASS | PASS С ПРЕДУПРЕЖДЕНИЯМИ | FAIL
- **Критические пункты:** что делает роль непригодной (отсутствие описания триггера,
  `Tools:` слишком широкий/узкий, модель не обоснована через `model-strategy`, не проверено разграничение
  с существующей ролью)
- **Предупреждения:** неоптимально, но работоспособно (напр. основная модель унаследована вместо
  распределённой, нет критерия ротации для долгоживущего Companion-Worker)
- **Пройденные проверки + рекомендации:** что соответствует, что делать дальше

## Связанные навыки

- `model-strategy` — выбор/распределение модели (шаг 3, здесь только ссылка).
- `swarm-operations` — паттерны роя для совместной работы нескольких ролей.
- `choose-your-orchestrator` — выбирает подходящий паттерн оркестрации.
- `orchestrator` — протокол декомпозиции/делегирования/приёмки.
- `agents-bridge` — межпровайдерные сообщения/присутствие/блокировки, если новая
  роль должна взаимодействовать за пределами Claude Code с Codex/Gemini/Kimi.
- `skill-explorer` — проверяет, существует ли уже способность, ПРЕЖДЕ чем создавать новую роль (предотвращение дублирования).
