# Decision Avatar

## Назначение

Этот skill не дублирует человека. Он предоставляет проверяемую процедуру для вывода вероятного предпочтения на основе подлинных, авторизованных доказательств для повторяющихся типов решений.

Используйте его только при наличии локального профиля решений и если его использование допустимо для текущей задачи. Без профиля skill не выдает суррогатного решения.

Использование считается авторизованным только в том случае, если задача, применимые правила агента или метаданные профиля явно разрешают текущую цель. Простая доступность файла профиля не является согласием.

## Ключевые принципы

1. **Доказательство важнее предположения.** Прямые заявления и подтвержденные решения имеют больший вес, чем выведенные шаблоны.
2. **Предсказание — это не заявление человека.** Выходные данные агента не должны возвращаться в профиль в качестве новых первичных доказательств.
3. **Принятие решения — это не исполнение.** Рекомендация может быть определенной, даже если ее реализация требует дополнительных полномочий.
4. **Молчаливое согласие — это не обратная связь.** Отсутствие возражений не подтверждает предсказание.
5. **Профили остаются локальными и приватными.** Не переносите личные данные, секреты или конфиденциальный контент в общие файлы навыков.

## Портативная модель профиля

Имена файлов свободно настраиваются; требуются только следующие роли:

| Роль | Содержание |
|---|---|
| Методология | Уровни доказательств, защита данных и правила калибровки |
| Подтвержденные предпочтения | Прямые заявления и подтвержденные решения |
| Гипотезы | Выведенные правила с уровнем уверенности и источниками |
| Действия | Действия, предпринятые на основе предсказания |
| Обратная связь | Подтверждение, исправление или отклонение человеком |

Более свежие решения, относящиеся к проекту, имеют приоритет над общими предпочтениями.

Каждое обработанное доказательство должно содержать как минимум:

```text
Quellen-ID:
Datum:
Entscheidungstyp und Gültigkeitsbereich:
Status: bestätigt/korrigiert/widerrufen
Gültig bis: <optional>
```

Не используйте отозванные, просроченные или выходящие за рамки их применимости доказательства. В случае противоречивых подтвержденных доказательств сначала побеждает более специфичное, а затем более свежее. Если конфликт сохраняется, установите уровень уверенности на «низкий» и эскалируйте.

## Цикл принятия решений

### 0. Проверка локального правила приоритета

Если для текущего проекта или конкретного типа решения существует подтвержденное правило, используйте его и задокументируйте его источник.

### 1. Поиск реальных доказательств

Используйте только те доказательства, которые допустимы в соответствии с локальной методологией. Списки задач, логи агентов, предыдущие ответы аватара и аргументы текущей сессии не являются заявлениями человека.

### 2. Формирование предсказания

Всегда выводите результат с обоснованием и одним из трех уровней:

- **высокий (high):** несколько прямых, последовательных и релевантных доказательств,
- **средний (medium):** правдоподобный шаблон с ограниченными или косвенными доказательствами,
- **низкий (low):** новая ситуация, противоречивые доказательства или отсутствие надежного шаблона.

Важные решения не становятся автоматически «низкими». Уверенность измеряет доказанность предпочтения, а не масштаб последующего исполнения.

### 3. Разделение режимов

| Режим | Результат | Побочный эффект |
|---|---|---|
| Предсказание | Вероятная позиция + доказательства + уверенность | нет |
| Решение | Конкретный выбор + обоснование + уверенность | нет |
| Действие | Авторизованная, безопасная реализация + лог действий | возможен |

В режиме Действия дополнительно применяются правила полномочий и безопасности среды выполнения. Низкая уверенность или отсутствие полномочий на исполнение ведут к эскалации, а не к молчаливому исполнению.

### 4. Калибровка обратной связи

После получения реальной обратной связи:

1. Отметьте предсказание как подтвержденное, исправленное или отклоненное.
2. Опционально зафиксируйте шкалу оценки.
3. Зафиксируйте различие между направленной ошибкой и ошибкой соответствия.
4. Скоректируйте гипотезу и уровень уверенности.
5. Переносите в подтвержденные предпочтения только подлинную обратную связь.

## Формат вывода

```text
Entscheidungstyp:
Modus:
Wahrscheinliche Präferenz:
Konfidenz:
Zulässige Belege:
Gegenbelege oder Unsicherheit:
Ausführung autorisiert: ja/nein
Nächster Schritt:
```

В выводах указывайте только отредактированные ID источников и сводку доказательств, необходимую для принятия решения. Не воспроизводите личные заявления, абсолютные пути к профилям или чувствительные необработанные данные.

## Ограничения

- Никакой диагностики или утверждений о внутренних состояниях человека.
- Никакого использования профиля за пределами его разрешенной цели.
- Никакого автоматического принятия предположений агента в качестве личных знаний человека.
- Никакого исполнения исключительно на основе предсказания, если для этого требуются новые полномочия.
