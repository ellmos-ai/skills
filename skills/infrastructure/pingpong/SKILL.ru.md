# PingPong

Эксплуатируйте две или более системы как радиостанции через общую папку синхронизации. Держите предметный контракт не зависящим от провайдера; отличается только адаптер продолжения.

## Определите режим

- ListenSync: ровно один систематический слушатель на хост. Он сканирует, принимает подходящие задания и при ответах также выполняет WriteSync.
- WriteSync: каждый работающий субъект может отправлять свои релевантные дельты, задания, новости и подтверждения получения. Этот режим не запускает слушатель.
- Если режим не указан, используйте ListenSync.

## Уточните участие (STATE и CALL)

Перед контрактом запуска двухступенчатая проверка определяет, есть ли вообще кто-то для связи. `scripts/pingpong_runtime.py check --slot <slot> --sync-root <pfad>` отвечает ровно тремя значениями: код выхода 0 `call-for-me` (активировать и запустить агента), код выхода 1 `idle` (я сам активен, деактивировать), код выхода 3 `check-failed` (нечитаемо, никогда не трактовать как простой). Участие требует одновременно STATE и CALL; тот, кто созывает Call, завершает его по достижении цели, иначе он истекает. Полные правила в references/protocol.md.

## Задайте контракт запуска

1. По умолчанию используйте 24h. Принимайте также относительные длительности вроде 15m, 2h, 3d или абсолютный момент окончания в ISO-8601.
2. Замерьте локальное время старта и укажите expires_at с датой, временем и часовым поясом.
3. Начинайте с 15 минут. Используйте каденцию из references/protocol.md, если пользователь не требует фиксированной каденции.
4. Определите выполнение цели так: достигнут конец срока, выполнен заключительный скан FileCommander, все до того момента обнаруженные подходящие входящие обработаны или точно заблокированы и задокументированы, State обновлён и собственный планировщик остановлен.
5. Без подтверждения FileCommander не утверждайте ни о сканировании, ни о достижении цели.

## Используйте адаптер провайдера

### Codex

Перед первым сканированием явно создайте сохраняемую цель с полным контрактом запуска и expires_at. За каждое продолжение выполняйте ровно один полный цикл сканирования. Не завершайте цель после пустого или успешного отдельного цикла. Затем фактически ждите до next_scan_at, например:

    python "<skill-root>/scripts/pingpong_runtime.py" wait --until "<next_scan_at>"

В момент истечения выполните заключительный цикл. Помечайте цель завершённой только при выполненном критерии успеха.

### Claude Code

Запускайте задачу как /loop <Kadenz> $pingpong. Если навык уже запущен из плановой задачи, не создавайте второй loop. При смене каденции заменяйте только собственное задание cron. Удалите его после заключительного цикла.

## Выполните цикл

Полностью прочитайте references/protocol.md и выполните ровно один описанный там цикл сканирования, обработки и State. Для каждого обращения к папке синхронизации используйте ellmos FileCommander. Листинг оболочки, запись планировщика или одно только имя файла не являются подтверждением сканирования.

При простое не придумывайте работу. Кратко сообщите: время сканирования, прочитанные файлы свежести, текущую каденцию, empty_runs, next_scan_at и expires_at.

## Выполните WriteSync

Пишите только в собственный слот системы или в явно глобальный канал. Укажите отправителя, получателя, время, связь, действие, результат, открытые пункты и желаемую каденцию. Объединяйте, а не перезаписывайте; никаких учётных данных; соблюдайте блокировки. После записи прочитайте канонический файл обратно через FileCommander.
