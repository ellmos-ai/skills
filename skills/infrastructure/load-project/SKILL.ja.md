# Load Project (プロジェクト読み込み)

## 目的

特定のプロジェクトタスクの開始時、または作業コンテキストが不明確になった場合にこのスキルを使用します。目的は完全なリポジトリ監査ではなく、安全に作業を継続するために必要な最小限の信頼できるコンテキストを特定することです。

## 設定

このスキルは固定のディレクトリ名を必要としません。ローカルインストールでは、オプションで一般的なエージェントルールまたはプロジェクトローカル設定で以下の値を定義できます:

- 既知のワークスペースルート、
- 優先されるファイルツール、
- 追加のブートまたはレジストリファイルの名前、
- ロックチェッカー、
- プロジェクト固有の役割と優先順位。

そのような設定がない場合、スキルは指定されたターゲットとそこで見つかるプロジェクトルールのみを使用して動作します。

## 手順

### 1. ターゲットの解決

1. 明示的なパス、プロジェクト名、または現在の作業フォルダを出発点とします。
2. 実際のプロジェクトまたはリポジトリのルートを特定します。
3. タスク、ルートドキュメント、およびリポジトリの境界に基づいて曖昧な一致を絞り込みます。ターゲットが実質的に異なる場合は推測しないでください。

### 2. ルール階層の読み込み

一般的なコンテキストから具体的なコンテキストへと読み進めます:

1. グローバルなエージェントおよび安全ルール、
2. ワークスペースまたはパイプラインルール、
3. プロジェクトおよびリポジトリルール、
4. タスク関連の指示。

より具体的なルールはそのスコープ内で適用されます。より上位のセキュリティおよび権限の境界は維持されます。

### 3. 役割に応じたルートドキュメントの読み込み

ファイル名は手掛かりであり、固定の規範ではありません。これらの役割を果たすドキュメントを意図的に探します:

| 役割 | 典型的な内容 |
|---|---|
| 導入 | 目的、ナビゲーション、開始指示 |
| ルール | 作業手順、言語、セキュリティ、規約 |
| アーキテクチャ | コンポーネント、データフロー、境界 |
| ステータス | 現在の状況、未解決の問題、最終確認 |
| タスク | 優先的に行うべき次の作業 |
| レジストリ | 正式なプロジェクト、チェック、または公開 |
| エビデンス | テスト、確認プロトコル、検証メモ |
| 引き継ぎ | 進行中の作業、サードパーティの変更、次のステップ |

具体的なタスクに関連する役割のみを読み込みます。

### 4. 拘束力のある参照の追跡

読み込んだルールが他のファイルを必読として明示的に指定している場合、それらをターゲットを絞って追加読み込みします。参照チェーンがタスクにこれ以上の拘束力のあるコンテキストを提供しなくなった時点で終了します。

### 5. 状態とロックの確認

- オーナー、スコープ、タイムスタンプ、および妥当性基準について、ローカルポリシーに基づいてロックを確認します。定義された期限切れルールがない場合、獨自の判断でロックを期限切れと宣言しないでください。
- バージョン管理ステータスおよびサードパーティの変更、
- 関連する場合、実行中のプロセスまたはチェックポイント、
- レジストリ、テスト、およびステータス詳細の最新性。

変更を加える前に、影響を受ける領域の初期状態をステータス/Diffのベースラインとして保存します。既存の変更を確実に特定できない場合は、予防措置としてサードパーティによるものとみなし、手を付けないでください。

スナップショットは特定時点の状態として扱い、リスクの高い操作を行う前に再検証してください。

### 6. 状況報告の作成

実施前に簡潔に記録します:

```text
Ziel:
Projekt-Root:
Geltende Regeln:
Evidenzquellen:
Snapshot-Zeitpunkt:
Relevanter Ist-Zustand:
Locks oder fremde Änderungen:
Erfolgskriterium:
Nächster sicherer Schritt:
```

ソース名は検証に必要な精度でのみ指定してください。機密情報、個人データ、および機密コンテンツをマスキング処理し、状況報告にコピーしないでください。

これによりタスクが明確で承認されている場合は、直接作業を進めてください。

## 限界・境界条件

- デフォルトで広範かつ無制限なファイル検索を行わない。
- 不足しているルールやレジストリを捏造しない。
- 古いステータスメッセージを現在のエビデンスとして扱わない。
- サードパーティの変更を上書きしない。
- 特定のタスクのコンテキストのみを読み込む場合に、プロジェクト全体のフルオンボーディングを実行しない。
