# ওয়ে-ফাইন্ডিং রাউটিং (স্ব-অভিমুখ নির্ণয় ও জরুরি ফলব্যাক ইঞ্জিন)

**ওয়ে-ফাইন্ডিং রাউটিং** স্কিলটি, যা **`survival-routing`**,
**`dead-reckoning`**, **`pathfinder-routing`** এবং **`celestial-routing`** নামেও পরিচিত,
LLM এজেন্টদের জন্য নেভিগেশন ও জরুরি পুনরুদ্ধারের একটি বাধ্যতামূলক কাঠামো হিসেবে কাজ করে।

এটি এজেন্টদের স্বাভাবিক কার্যনির্বাহের জন্য সক্রিয় ওয়ে-ফাইন্ডিং হিউরিস্টিক এবং প্রসঙ্গ-বিচ্যুতি, পুনরাবৃত্ত কার্যনির্বাহ-ত্রুটি, ব্যর্থ API বা বন্ধ পথের জন্য জরুরি প্রোটোকল দিয়ে সজ্জিত করে।

---

## সমার্থক শব্দ ও কৌশলের সারসংক্ষেপ

| সমার্থক কৌশল | রূপক ও মূল নীতি | ব্যবহারের ক্ষেত্র |
| :--- | :--- | :--- |
| **`wayfinding-routing`** (প্রধান) | **ওয়ে-ফাইন্ডিং / স্থানিক অভিমুখ নির্ণয়:** বাহ্যিক GPS ছাড়া দিকনির্দেশক চিহ্ন ও পরিবেশগত সূত্র দিয়ে নেভিগেশন। | Sidecar, `workflowhooker` এবং `automation-self-care`-এর প্রাথমিক নেভিগেশন লুপ। |
| **`survival-routing`** | **জরুরি ফলব্যাক ও আত্মরক্ষা:** টুল ব্যর্থ হলে বা লুপ তৈরি হলে সার্কিট-ব্রেকিং ও নিয়ন্ত্রিত অবনতি। | টাইমআউট, বারবার ত্রুটি বা অনুমতির সীমায় জরুরি পুনরুদ্ধার। |
| **`dead-reckoning`** | **নৌ-নেভিগেশনের ডেড রেকনিং:** বাহ্যিক অবস্থা-উৎস ছাড়া ধাপে ধাপে ব্রেডক্রাম্ব থেকে সঠিক অবস্থা পুনর্গঠন। | Scratch ফাইল বা `TODO.md`-এ কার্যধাপ অনুসরণ করে নির্ভুলভাবে ফিরে যাওয়া। |
| **`pathfinder-routing`** | **পথপ্রদর্শক ও অগ্রগামী দল:** মাল্টি-এজেন্ট দলের জন্য পথগুলো আগে থেকে পরীক্ষা ও প্রস্তুত করা। | ডিরেক্টরি ট্রি, লক ও টাস্ক নির্ভরতার প্রি-ফ্লাইট যাচাই। |
| **`celestial-routing`** | **জ্যোতির্বিদ্যাগত নেভিগেশন:** স্থানীয় প্রসঙ্গ অস্পষ্ট হলে অপরিবর্তনীয় ধ্রুবতারা-অ্যাঙ্কর ডকুমেন্টের সাথে সারিবদ্ধ হওয়া। | প্রম্পট নির্দেশনা পরস্পরবিরোধী হলে `CLAUDE.md`, `AGENTS.md` এবং `START.md`-এ ফিরে যাওয়া। |
| **কৌশল `likelihood-routing`** (আলাদা স্কিল, ইনস্টল থাকলে) | **সম্ভাব্যতা-গ্রেডিয়েন্ট একটি উষ্ণ/শীতল সেন্সর হিসেবে:** শর্তসাপেক্ষ পরবর্তী-সম্ভাব্যতা (Likelihood Scoring) দিয়ে নিয়ন্ত্রণ ফাইল মূল্যায়ন করে গ্রেডিয়েন্ট ($\Delta S$) অনুসরণ করা। | কোনো মেমরি সেবা ছাড়া ফলব্যাক, যখন কোনো প্রকল্প-নির্দিষ্ট পরিভাষা সেশন ইতিহাসে নেই। |

## পাঁচটি মূল জরুরি ও অভিমুখ নির্ণয় প্রোটোকল

### 1. `PROTOCOL-ANCHOR-RESET` (ধ্রুবতারা ফলব্যাক / Celestial Routing)

- **ট্রিগার:** প্রসঙ্গ-বিচ্যুতি, পরস্পরবিরোধী ব্যবহারকারী নির্দেশনা, বা দীর্ঘ, বহু-টার্নের সেশনে অভিমুখ হারানো।
- **হিউরিস্টিক নিয়ম:** মুক্ত পাঠ্য তৈরি থামান। ক্ষণস্থায়ী অনুমান বাতিল করুন। রুট অ্যাঙ্কর ডকুমেন্ট (`CLAUDE.md`, `AGENTS.md`, `START.md`) পুনরায় পড়ুন। আরও কার্যক্রমের আগে লক্ষ্য অবস্থাকে কর্তৃপক্ষীয় রুট নির্দেশে রিসেট করুন।

### 2. `PROTOCOL-STOP-EXPLAIN` (রাবার-ডাক প্রতিফলন লুপ)

- **ট্রিগার:** একটি টার্মিনাল কমান্ড, ফাইল পরিবর্তন বা API অনুরোধ একই ত্রুটিতে দুবার ব্যর্থ হয়।
- **হিউরিস্টিক নিয়ম:** **কমান্ড কার্যনির্বাহ লক করুন।** তৃতীয় চেষ্টার আগে এজেন্টকে একটি আনুষ্ঠানিক স্ব-প্রতিফলন দিতে হবে:
  1. *চেষ্টা ১ ও ২-তে সুনির্দিষ্টভাবে কী ত্রুটি হয়েছিল?*
  2. *পূর্ববর্তী রোগ-নির্ণয় অনুমানটি কেন ব্যর্থ হলো?*
  3. *কোন নতুন বিকল্প পদ্ধতি বেছে নেওয়া হচ্ছে?*
  এই স্পষ্ট যুক্তির পরেই কার্যনির্বাহ আনলক হবে।

### 3. `PROTOCOL-GRACEFUL-DEGRADATION` (বহু-স্তরের ফলব্যাক ক্যাসকেড)

- **ট্রিগার:** প্রাথমিক টুল, MCP সার্ভার বা বাহ্যিক API অনুপলব্ধ বা ত্রুটি দিচ্ছে।
- **হিউরিস্টিক নিয়ম:** কখনো হঠাৎ ব্যর্থ হবেন না বা অন্ধভাবে লুপ করবেন না। ধাপে ধাপে অবনমিত হোন:
  - **স্তর ১ (সর্বোত্তম):** সম্পূর্ণ নেটিভ API বা MCP টুল
  - **স্তর ২ (বিকল্প টুল):** স্থানীয় Python CLI বা স্ক্রিপ্ট
  - **স্তর ৩ (শুধু-পড়া অবস্থা):** সরাসরি ফাইল মূল্যায়ন
    (`view_file` বা কাঁচা পাঠ্য)
  - **স্তর ৪ (হস্তান্তর):** ব্যবহারকারীর জন্য একটি কাঠামোগত অবস্থা প্রতিবেদন ও খোলা বিকল্পসমূহ উপস্থাপন করা।

### 4. `PROTOCOL-BREADCRUMB-BACKTRACK` (ডেড রেকনিং ও বন্ধ-পথ শনাক্তকরণ)

- **ট্রিগার:** একটি জটিল বহু-ধাপের রিফ্যাক্টরিং বা ওয়ার্কফ্লো পথ ধাপ N-এ অমীমাংসিত অচলাবস্থায় পৌঁছায়।
- **হিউরিস্টিক নিয়ম:** ধ্বংসাত্মক পরিবর্তনের আগে ব্রেডক্রাম্ব রেকর্ড করুন। পথ ব্যর্থ হলে:
  1. কমিট-হয়নি এমন পরিবর্তন প্রত্যাহার করুন এবং অবস্থা পুনরুদ্ধার করুন।
  2. সর্বশেষ পরিষ্কার ব্রেডক্রাম্ব চেকপয়েন্টে ফিরে যান।
  3. ব্যর্থ রুটটিকে `TODO.md`-এ অবরুদ্ধ হিসেবে চিহ্নিত করুন।
  4. বিকল্প পথ B চেষ্টা করুন।

### 5. `PROTOCOL-CIRCUIT-BREAKER` (জরুরি বন্ধ ও নিরাপদ প্রস্থান)

- **ট্রিগার:** কার্যনির্বাহ সীমা পৌঁছেছে, অসীম লুপ শনাক্ত হয়েছে, বা গুরুতর সিস্টেম-লক ত্রুটি ঘটেছে।
- **হিউরিস্টিক নিয়ম:** জরুরি শাটডাউন চালান:
  1. নিজের অর্জিত সব ফাইল ও Git লক মুক্ত করুন
     (`python -m workflowhooker check`)।
  2. বর্তমান আংশিক অবস্থা `.SYNC/SURVIVAL_STATE.json` বা
     `AUTOMATIONS-MEMORY.md`-এ সংরক্ষণ করুন।
  3. ঘটনাটি `ANTIGRAVITY-LOG.txt`-এ লগ করুন।
  4. ব্যবহারকারী বা অর্কেস্ট্রেটরের জন্য একটি কার্যকর সারসংক্ষেপসহ পরিচ্ছন্নভাবে শেষ করুন।

## `automation-self-care` ও `workflowhooker`-এর সাথে সমন্বয়

`wayfinding-routing` নিচের বিষয়গুলোর জন্য অন্তর্নিহিত নেভিগেশন যুক্তি সরবরাহ করে:

- **`automation-self-care`**: পাঁচটি প্রোটোকলের বিরুদ্ধে Sidecar প্রম্পট পরীক্ষা করে স্ব-নিরাময় সক্ষমতা যাচাই করে।
- **`workflowhooker`**: ধাপে ধাপে লক যাচাই ও ব্রেডক্রাম্ব লগিংয়ের জন্য ডিফল্ট হিউরিস্টিক দেয়।
- **`staircase-routing`**: উল্লম্ব ডিরেক্টরি নেভিগেশনের জন্য `PROTOCOL-ANCHOR-RESET` ব্যবহার করে।
- **কৌশল `likelihood-routing`** (আলাদা স্কিল, ইনস্টল থাকলে): নিয়ন্ত্রণ ফাইল যখন একাধিক সম্ভাব্য শাখার দিকে অস্পষ্টভাবে নির্দেশ করে, তখন `PROTOCOL-ANCHOR-RESET`-এর জন্য উষ্ণ/শীতল সেন্সর হিসেবে সম্ভাব্যতা-গ্রেডিয়েন্ট প্রদান করে — `staircase-routing`-এর পরিপূরক, যা কীওয়ার্ড মিলের ভিত্তিতে খোঁজে, গ্রেডিয়েন্টের ভিত্তিতে নয়।
