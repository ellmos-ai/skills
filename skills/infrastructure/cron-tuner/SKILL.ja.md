# cron-tuner — 自己調整型のタイミング制御ループ

定期的なスケジュール駆動の作業（cronジョブ、計画タスク、タイマー）のための**自己調整型**制御ループです。固定の間隔ではなく、ジョブ自身が自らの実行間隔を調整します。作業があれば間隔を短くし、無活動が続けば間隔を長くします。ホストやプラットフォームに依存せず、このパターンはあらゆるスケジューラーで機能します。

## 使用するタイミング

- 定期的なスキャン（メールボックス監視、Sync-Yardスキャン、キューのポーリング）で、アクティブな「マッチ」の間は素早く反応し、アイドル期間中は低コストに保ちたい場合。
- 調整を**監査可能**にしたい場合（会話や担当者の頭の中に暗黙的に残すのではなく、状態ファイルとして残す）。

## 概念

- **制御ループ**: 計測 → 判断 → 実行 → 永続化。各実行は状態の書き込みで終わり、各実行は状態の読み込みで始まります。
- **活性化**: 新しい作業を見つけたら、すぐに最も短い間隔に切り替えます。
- **クールダウン・ラダー**: 空の実行が続くと、ラダーを一段ずつ下げます。各段階は、間隔が実際に変わる場合にのみ適用されます。
- **上限**: 定義された最大間隔を決して超えて緩めません。

## 参照スキーマ

| 条件 | 新しい間隔 |
|---|---|
| 新しい作業を発見 | 最短（例: 15分） |
| 連続4回の空の実行 | 30分 |
| 連続6回の空の実行 | 1時間 |
| 空の実行がさらに続くごと | 倍増（2時間、4時間、8時間） |
| 上限 | 24時間（これを超えない） |

しきい値は作業量に合わせて調整してください。倍増は単純に、上限は明示的に保ちます。

## 状態ファイル（必須）

ワーカーごとに小さなJSONファイルを用意します（例: `cron-tuner-state.json`）:

```json
{
  "empty_runs": 0,
  "interval_minutes": 15,
  "note": "cron-tuner state"
}
```

ルール:

1. **記憶ではなくファイル。** カウンターは、コンテキストの圧縮、セッションの再起動、オペレーターの交代を乗り越えられ、人間や他のエージェントが確認できる必要があります。間隔を会話履歴の中で追跡しないでください。
2. **変更時のみジョブを再作成する。** 状態は毎回の実行で永続化しますが、予定されたジョブは間隔が実際に変わる場合にのみ置き換えます。
3. **新しいジョブ = 新しいスケジュール、同じ状態。** 間隔の切り替えとは、古いジョブを削除し、新しい間隔で新しいジョブを作成することを意味します。カウンターはそのまま継続します。

## 運用ルール

- **気分ではなく作業が決定する。** 観測された到着のみが間隔を変えます。期待や推測では決して変えません。
- **群れ効果を避けるオフセット。** 最短間隔では、毎時ちょうどや毎時30分の時刻を避けます（例: 7/22/37/52分）。これにより、複数のエージェント群（フリート）が足並みをそろえて実行されることを防ぎます。
- **フェイルセーフ:** 連携先のシステムが沈黙した場合は、通常の空席／不在（Vakanz/Abwesenheit）のルールに従います。チューナーがポーリングの洪水にエスカレートすることはありません。
- **証跡:** 間隔を変えるたびに、理由、旧間隔、新間隔を記録します。

## 拡張性（ループ種別のレジストリ）

このスキルは、将来的に追加される自己調整型ループ種別の拠り所となります:

- **cooldown**（本スキーマ: 無活動 → 間隔を長くする）
- **backoff**（エラー → 間隔を長くする、成功 → 間隔を短くする）
- **burst**（到着の急増 → 終了時刻を明示した一時的な高速モード）
- **wake-assist**（外部からのウェイクメッセージ → サイクル外での即時実行）

新しいループ種別は、ここにサブセクションと、それ専用の状態ファイルのスキーマを追加します。
