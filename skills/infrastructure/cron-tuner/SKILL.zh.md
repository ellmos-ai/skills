# cron-tuner — 自调节节拍反馈环

一个用于周期性、按计划触发工作（cron 任务、计划任务、定时器）的**自调节**反馈环。任务不使用固定间隔，而是调整自身节拍：有工作时加快，静默时放缓。与宿主和平台无关；该模式适用于任何调度器。

## 何时使用

- 周期性扫描（邮箱监视、Sync-Yard 扫描、队列轮询）需要在活跃"匹配"期间快速响应，并在空闲期保持低成本。
- 调整必须**可审计**（通过一个状态文件），而不是隐含在某次对话或某个人的记忆里。

## 概念

- **反馈环**：测量 → 决策 → 执行 → 持久化。每次运行以写入其状态结束；每次运行以读取其状态开始。
- **激活**：发现新工作 → 直接跳到最快间隔。
- **冷却阶梯**：空运行沿阶梯逐级下降；只有间隔确实发生变化时，每一级才生效。
- **上限**：间隔绝不超过已定义的最大值。

## 参考方案

| 条件 | 新间隔 |
|---|---|
| 发现新工作 | 最快（例如 15 分钟） |
| 连续 4 次空运行 | 30 分钟 |
| 连续 6 次空运行 | 1 小时 |
| 每次额外的空运行 | 翻倍（2 小时、4 小时、8 小时） |
| 上限 | 24 小时（绝不更高） |

阈值应根据工作负载调整；保持翻倍规则简单，并明确写出上限。

## 状态文件（必需）

每个 worker 一个小型 JSON 文件，例如 `cron-tuner-state.json`：

```json
{
  "empty_runs": 0,
  "interval_minutes": 15,
  "note": "cron-tuner state"
}
```

规则：

1. **以文件为准，而非记忆。** 计数器必须能经受上下文压缩、会话重启和操作员更替，并且对人和其他智能体可见。不要在对话历史中追踪节拍。
2. **仅在变化时重写。** 每次运行都持久化状态，但只有间隔确实变化时才替换计划任务。
3. **新任务 = 新计划，同一状态。** 节拍变化意味着删除旧任务并以新间隔创建新任务；计数器继续累计。

## 运行规则

- **以工作为准，而非情绪。** 只有观察到的到达才能改变节拍——绝不依据预期或估计。
- **防止群聚偏移。** 对于最快间隔，避开整点和半点标记（例如第 7/22/37/52 分钟），以免整群实例同时触发。
- **失效保护：** 若伙伴系统沉默，则适用常规的空缺/缺席规则——调节器绝不会升级为轮询洪流。
- **证据：** 每次节拍变化都要记录原因、旧间隔和新间隔。

## 可扩展性（循环类型注册表）

该技能是今后更多自调节循环类型的归属：

- **cooldown**（本方案：静默 → 变慢）
- **backoff**（出错 → 变慢，成功 → 变快）
- **burst**（到达高峰 → 带明确结束点的临时快速模式）
- **wake-assist**（外部唤醒消息 → 在周期之外立即运行）

新的循环类型应在此处增加一个小节，并附带其自身的状态文件方案。
