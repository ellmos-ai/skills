# توجيه الشخصيات الدلالي

وجّه أولًا حسب القدرة، ثم طبّق الشخصية بعد ذلك. أنشئ خريطة قابلة للنقل تفصل بين اختيار الدور الدلالي والبحث الحتمي عن نقطة النهاية والتحميل الخاص بالمزوّد.

## نموذج التوجيه

```text
Anfrage
  -> semantische Domäne oder koordinierende Rolle
  -> Expertenfähigkeit
  -> ausdrücklich angegebener oder live aufgelöster Skill-Endpunkt
  -> optionales Persona-Overlay
  -> Anbieteradapter lädt und führt aus
```

تتحكم الشخصية في أسلوب التواصل والأولويات وأنماط التفاعل. ولا تمنح أدوات أو صلاحيات أو قدرات متخصصة. يُنسّق الدور العمل، ويحدد الخبير نطاق المجال، والمهارة هي نقطة النهاية القابلة للتنفيذ.

## إنشاء خريطة التوجيه

استخدم البيانات الوصفية الصريحة مصدرًا معتمدًا، واستخدم التشابه المعجمي لاختيار المرشحين فقط:

```bash
python scripts/build_routing_map.py \
  --roles-dir path/to/roles \
  --personas-dir path/to/personas \
  --skills-dir path/to/skills \
  --out routing-map.json
```

يفهم المنشئ الحقول الشائعة في `SKILL.md` مثل `type`،
و`orchestrates.experts`، و`parent_agents`، و`skills`، والأوصاف والمصدر.
ويُنشئ خريطة وقت التشغيل دون الحاجة إلى تثبيت النظام المصدر.
اقرأ [routing-map-schema.md](references/routing-map-schema.md) قبل توسيع الصيغة.

كل معرّف مهارة مُصدَّر فريد. إذا أعلنت عدة ملفات مصدر المعرّف الثابت نفسه، يختار المنشئ بشكل حتمي المسار النسبي الأول أبجديًا ويسجل مشكلة `duplicate-skill-id`، ولا يُخرج أبدًا مدخلين للمهارة بالمعرّف نفسه. تُطبَّع مراجع المهارات المُعلَنة في الخبراء والشخصيات إلى معرّف منقّى فقط إذا كان هذا المعرّف موجودًا في السجل المُصدَّر. تبقى المراجع المعطوبة والمجهولة والمُطبَّعة مرئية في `issues`، ولا تتحول المراجع المجهولة أو غير الصالحة أبدًا إلى نقاط نهاية أو روابط توافق للشخصيات.

لا ترفع مستوى `candidate_skills` تلقائيًا. أكّده أولًا عبر مُحلِّل مهارات نشط أو بيانات وصفية للمصدر.

## إنشاء الشخصيات وتخزينها

يُنشئ النواة الخرائط ولا يخترع الشخصيات. من يريد استخدام شخصياته الخاصة يخزنها **بجانب المهارة** ويعيد بناء الخريطة:

```text
semantic-persona-routing/
  personas/<persona-id>.md          # eine Datei je Persona
  roles/<rolle>/SKILL.md            # koordinierende Rollen und Experten
  routing-map.json                  # erzeugte Karte
  config.json                       # host-lokal, nie veröffentlicht
```

يقرأ المنشئ الأدوار حصريًا من ملفات `SKILL.md`، ويقرأ الشخصيات من كل ملف Markdown يحتوي على Frontmatter. انسخ
[templates/persona.template.md](templates/persona.template.md) إلى
`personas/<persona-id>.md` واملأ العقد:

| الحقل | المعنى |
|---|---|
| `name`، `type: persona` | معرّف الشخصية الثابت ونوعها |
| `persona.display_name`، `short_name`، `gender`، `role`، `default_prompt` | الاسم المعروض، والاسم المختصر، وصيغة المخاطبة، والدور في جملة واحدة، وجملة الاستدعاء الخاصة بالمزوّد |
| `parent_agents` | الأدوار التنسيقية المرتبطة بالشخصية |
| `skills` | **أسماء المهارات، وليس المسارات أبدًا** — هذه وحدها تُحل إلى نقاط نهاية |
| `optional_skills` | المهارات المرتبطة بالمضيف؛ إذا غابت تبقى `GAP` مرئية |

لا يجوز للشخصية أن تمنح أو تتجاوز الأدوات والصلاحيات وقرارات الأمان أو القفل أو المستخدم؛ إنها طبقة فوق الدور والمهارات.

**المسارات:** لا تُسمّي المهارة مسارات المضيف. يوضح `config.example.json` النمط
(`ellmos.skill-config.v1`، و`einstellungen.paths` مع عناصر نائبة مثل
`<HOME>/<ONEDRIVE>/<TOPICS>`)؛ تُسمى النسخة المحلية في المضيف `config.json`،
وتُحفظ أثناء النشر ولا تُضاف إلى المستودع أبدًا.

**تنظيف الكتالوج:** تُنتج مكتبة المهارات التي تحتوي على أرشيفات أو نسخ مرجعية كثيرًا من مشكلات `duplicate-skill-id`. يأخذ `--skills-layout catalog` فقط `<kategorie>/<name>/SKILL.md`، ويتخطى المجلدات ذات البادئة `_` (`_archive`، و`_reference`، و`_templates`):

```bash
python scripts/build_routing_map.py \
  --roles-dir roles --personas-dir personas \
  --skills-dir path/to/skills --skills-layout catalog \
  --out routing-map.json
```

## توجيه طلب

### 0. عرض الشخصيات المتاحة

إذا كانت الشخصيات موجودة بجانب المهارة (`personas/`)، فاعرضها عند الاستدعاء مع الاسم المعروض والدور والمهارات، ووجّه إلى المناسبة منها؛ وإذا لم يذكر الطلب شخصية، فاختر واحدة فقط في الخطوة 4. يبقى تنسيق إثبات التوجيه دون تغيير.

### 1. اختيار الدور التنسيقي دلاليًا

قارن الطلب بأسماء الأدوار وأوصافها وحالات استخدامها. فضّل أضيق دور قادر على تنسيق الطلب بأكمله. عند انخفاض الثقة، أبقِ عدة مرشحين مرئيين، ولا تسأل المستخدم إلا إذا كان الاختيار يغيّر النتيجة بشكل جوهري.

### 2. اختيار الخبراء داخل الدور

استخدم فقط الخبراء المرتبطين بالدور التنسيقي المختار، ما لم يشمل الطلب بوضوح عدة أدوار. يجوز لطلب الخبير المباشر أن يتجاوز الدور التنسيقي عند التنفيذ، لكنه يحتفظ بارتباطه في شرح المسار.

### 3. تحديد نقاط النهاية القابلة للتنفيذ

حدّد بهذا الترتيب:

1. `endpoint_skills` من البيانات الوصفية الصريحة للمصدر أو المصدر الدقيق؛
2. مُحلِّل مهارات خارجي حديث أو باحث مهارات محلي؛
3. `candidate_skills` المُتحقّق منها؛
4. `GAP` مرئية عند عدم وجود نقطة نهاية.

لا تُوجّه أبدًا إلى اسم خبير كما لو كان مهارة مثبتة. نقطة النهاية المفقودة فجوة في النقل وليست إذنًا باختراع نقطة نهاية.

اقرأ [endpoint-resolution.md](references/endpoint-resolution.md) عند ربط سجل نشط، أو باحث معجمي، أو محمّل مهارات خاص بالمزوّد.

### 4. تطبيق طبقة الشخصية

اختر شخصية مرتبطة بالدور أو الخبير المختار. إذا انطبقت عدة شخصيات، ففضّل الشخصية التي تتوافق حدودها المعلنة وأسلوبها مع المهمة. لا تُطبّق شخصية إذا لم تكن مرتبطة بشكل صريح.

لا يجوز لتعليمات الشخصية أن تتجاوز قواعد الأمان أو الأقفال أو قرارات المستخدم أو الحدود المهنية أو صلاحيات الأدوات.

### 5. التحميل والتنفيذ

استخدم آلية تحميل المهارات أو الوكلاء الأصلية للمزوّد. قبل التنفيذ، حمّل تعليمات المهارات النشطة المختارة. أبقِ الموجِّه خفيفًا؛ فالتنفيذ من مسؤولية العامل أو الوكيل الحالي الذي يحمل المهارات.

## إثبات التوجيه

أعد أو سجّل ما يلي:

```text
ROLE: <koordinierende Rolle oder direct>
EXPERT: <Experte oder n/a>
SKILLS: <verifizierte aktive Endpunkte>
PERSONA: <Overlay oder none>
RESOLUTION: explicit | provenance | live-resolver | verified-candidate | GAP
CONFIDENCE: high | medium | low
WHY: <ein kurzer Grund>
GAPS: <fehlende Endpunkte oder Warnungen vor veralteten Karten>
```

أعد إنشاء الخريطة عند تغيّر أدوار المصدر أو مخزون المهارات. يجوز لمُحلِّل نشط أن يتجاوز خريطة قديمة فيما يخص توفر نقطة النهاية، لكن لا يجوز له إعادة كتابة تصنيف الأدوار الدلالي بصمت.

## مثال

الطلب: «رتّب إيصالاتي وجهّز ملخصًا للسنة الضريبية.»

يختار الموجِّه تنسيق المكتب، ثم خبير الضرائب، ثم يحدد مهارة الضرائب المثبتة، وأخيرًا يطبّق شخصية ضريبية دقيقة مرتبطة صراحةً. فإذا وُجد خبير الضرائب دون مهارة ضرائب قابلة للنقل، يُبلغ عن `GAP` ولا يتابع إلا عبر مسار بديل مُعدّ صراحةً.
