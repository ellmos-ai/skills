# Skill-Extractor — Извлечение навыков из историй чата (Русский)

## Обзор и назначение

Ценные методы работы рождаются в сессиях: проблема была с трудом решена, пользователь несколько раз вносил исправления, и в итоге получился рабочий процесс — но в следующий раз агент снова начинает с нуля. Этот навык дистиллирует из истории чата то, что стоит сохранить, и превращает это в навык по конвенциям локальной библиотеки навыков. Основной принцип: **Расширять перед созданием нового** — если существует очень похожий навык, он улучшается вместо создания дубликата.

Разграничение: Результатом здесь является **вызываемый навык** (способность/процедура, которую агент загружает при необходимости). Если история должна стать **автономной автоматизацией** (повторяющийся промпт, cron, расписание), используйте родственный навык `workflow-extract`.

## Процесс

### 1. Определение источника

Три формы ввода:

| Источник | Доступ |
| --- | --- |
| **Текущая сессия** | Использовать контекст разговора напрямую — файлы не требуются |
| **Отдельные транскрипты** | Чтение файлов; расположение и парсинг: `transcript-quellen.md` |
| **Пакетный режим (много старых историй)** | Сначала сокращение данных через субагентов, затем извлечение: раздел «Пакетный режим» |

### 2. Поиск ценного для извлечения

Не каждая сессия содержит навык. Ищите следующие сигналы — они показывают, где скрываются знания, полученные с трудом, которые понадобятся снова:

- **Повторение:** Один и тот же процесс встречался ≥2 раз (в этой сессии или в нескольких сессиях).
- **Циклы коррекции:** Пользователь неоднократно корректировал агента, пока результат не стал правильным — финальная версия является дистиллятом, а исправления — обоснованиями («почему именно так»).
- **Явные маркеры:** «запомни это», «мы всегда так делаем», «в следующий раз делай сразу так».
- **Цепочки инструментов:** Неочевидная последовательность инструментов/команд, которая сработала (включая тупики, которых следует избегать).
- **Правила принятия решений:** Критерии, по которым делался выбор между альтернативами.

Фиксируйте для каждого кандидата: Триггер (когда это нужно), Процесс (шаги), Обоснования (почему так, а не иначе), Подводные камни (что пошло не так), Форма результата.

### 3. Фильтр дубликатов (Dedup Gate): Расширять перед созданием нового

Прежде чем что-либо писать, проверьте существующий ландшафт:

1. Выполните поиск ключевых слов кандидата по каталогам навыков (папка развертывания агента, например `~/.claude/skills/`, и — при наличии — курируемая библиотека навыков как единый источник правды; а также зарегистрированные навыки плагинов).
2. Действительно **прочитайте** 2–3 наиболее близких навыка, а не просто сравните названия.
3. Примите решение:

| Результат | Действие |
| --- | --- |
| Кандидат в основном уже охвачен | **Расширить:** включить отсутствующие элементы в существующий навык (новый раздел, новая техника, новый подводный камень), увеличить MINOR-версию, добавить запись в журнал изменений |
| Частичное совпадение, но другое ядро | **Новый навык** с перекрестной ссылкой («Связанные навыки») на соседние навыки — не дублировать контент, а ссылаться на него |
| Ничего похожего | **Новый навык** |

Практическое правило: Если более половины кандидата содержится в существующем навыке, выполняйте расширение. Репозиторий навыков, полный почти одинаковых двойников, хуже, чем один хорошо ухоженный навык.

### 4. Нейтрализация

Сырой материал полон специфичных для сессии деталей. Перед написанием абстрагируйте по правилам из `neutralisierung.md`: отделите механику (общеприменимую) от конфигурации (специфичной для пользователя/системы), замените конкретные пути/хосты/имена заполнителями или четко помеченным блоком конфигурации. Цель: Навык работает для других пользователей, других систем, других проектов.

### 5. Написание навыка

- **Формат:** Соблюдайте конвенции целевой библиотеки (Frontmatter, схема наименования, язык, журнал изменений). В этой библиотеке: `docs/CONVENTIONS.md` (полный заголовок YAML, имя в kebab-case, немецкий язык как основной, семантическое версионирование).
- **Формулируйте Description активным образом:** description является триггерным механизмом. Записывайте как ЧТО делает навык, так и КОГДА он должен срабатывать (типичные формулировки пользователей) — навыки чаще срабатывают слишком редко, чем слишком часто.
- **«Почему» перед «Что»:** Переносите обоснования из циклов коррекции в навык. Навык, который только перечисляет шаги, будет неправильно применен при первом же особом случае; навык, объясняющий причины, можно адаптировать.
- **Документируйте подводные камни:** Тупики из сессии — на вес золота; включайте их как раздел «Красные флаги» или «Подводные камни».
- **Сохраняйте лаконичность:** Менее ~300 строк; выносите подробные материалы в справочные файлы, на которые ссылается `SKILL.md`.

### 6. Командный обертка (опционально)

Если навык должен регулярно вызываться напрямую, создайте слэш-команду (для Claude Code: короткий файл Markdown в `~/.claude/commands/<name>.md`, указывающий на навык и передающий аргументы). Конвенция: Команда = тонкая точка входа, содержимое живет в навыке.

### 7. Регистрация и тестирование

- Разместить в библиотеке (правильная категория) и развернуть в окружении (здесь: `python skill_sync.py deploy <name>` — для первичной установки требуется явное указание имени).
- Тест триггера: Сформулируйте 2–3 реалистичных промпта, которые должны активировать навык, и проверьте, срабатывает ли description.
- Для полного цикла оценки (тестовые случаи, сравнение с базовым уровнем, оптимизация описания) используйте `skill-creator`, если он установлен — данный навык является экстрактором, а не тестовой лабораторией.
- Ведение индекса/маршрутизации: Обновите навыки поиска/индекса навыков при их наличии (здесь: `code-skill-index`, таблица маршрутизации `skill-finder`).

## Пакетный режим: много старых историй чата

Транскрипты имеют большой объем (часто >100k токенов); никогда не загружайте их все в сыром виде в один контекст.
Map-Reduce через субагентов (шаблон: навык `swarm-operations`, рой задач):

1. **Инвентаризация:** Перечислите файлы транскриптов (расположение: `transcript-quellen.md`), сгруппируйте по проектам/периодам. При очень больших объемах сначала сократите с помощью существующих коллекторов/экстракторов (например, датасетов слушателей промптов/исследований, содержащих только промпты пользователей) — промпты пользователей + исправления несут наибольшее количество сигнала.
2. **Map:** По одному субагенту на пакет с четким заданием: «Прочитай эти транскрипты, передай кандидатов в навыки в виде компактного списка (триггер, процесс, обоснования, подводные камни, исходная сессия)» — возвращать только дистилляты, никогда не сырой текст.
3. **Reduce:** Объединить списки кандидатов, сгруппировать, объединить дубликаты. Частота имеет значение: Шаблон, появляющийся в 5 сессиях, является более сильным кандидатом, чем однократная уловка.
4. **Фильтр + Создание:** Для лучших кандидатов выполните шаги 3–7 обычного процесса. Предоставьте пользователю пронумерованный список кандидатов на выбор перед массовым созданием — иначе пакетное извлечение породит мусорные навыки.

## Пример и применение

```text
User: „Wir haben jetzt dreimal PDF-Rechnungen nach demselben Schema geparst —
mach daraus einen Skill."

1. Quelle: aktuelle Session. Signal: Wiederholung (3×) + Korrektur („Beträge immer
   als Dezimalzahl mit Punkt, nicht Komma").
2. Dedup-Gate: Suche findet `pdf`-Skill (generisch, Erzeugung/Extraktion) — Kern
   überlappt nicht (hier: Rechnungs-Schema + Validierungsregeln) → neuer Skill
   `invoice-parsing` mit Querverweis auf `pdf`.
3. Neutralisieren: konkreter Ablageordner und Firmenname → Konfigurationsblock.
4. Skill schreiben: Schema-Tabelle, die Komma/Punkt-Korrektur als Fallstrick,
   Changelog 1.0.0. Trigger-Test mit „lies diese Rechnung ein".
```

## Красные флаги

| Мысль | Реальность |
| --- | --- |
| «Я быстро создам новый навык» | Сначала фильтр дубликатов — расширять перед созданием нового. |
| «Я оставлю пути, это ведь для этой системы» | Нейтрализация обязательна; конкретика относится к блоку конфигурации. |
| «История длинная, я суммирую по памяти» | Ищите сигналы (исправления, маркеры) целенаправленно — память сглаживает именно те детали, которые делают навык ценным. |
| «Каждая сессия дает навык» | Без сигналов повторения/коррекции/маркеров: навыка нет. |

## Связанные навыки

- `workflow-extract` — такое же извлечение, но целью является автономная автоматизация.
- `skill-explorer` — аудит/очистка ландшафта навыков (использует фильтр дубликатов в масштабе).
- `skill-creator` (плагин) — цикл оценки и оптимизация описания для готовых навыков.
- `swarm-operations` — шаблон роя для пакетного режима.
